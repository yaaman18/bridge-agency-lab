# 同異転移の事前レビュー（2026-11-18）

対象は discussion/notes/D-memory-transfer-codex.md。判定は仕様への条件付き提案。測定結果はまだない。

## 何を測れば「覚えた」と言えるか

同じ初期状態から二条件に分け、訓練の記号・順序を共通にして X/Y の割当てだけを逆にする。試験時は外部の条件名、教師信号、訓練履歴、イベントキューの残りを読み出せないようにする。各問を同じ訓練終了時点の複製から開始する。確率的な実装では、二条件で試験時の乱数列も対にする。

〔判断点〕主張の対象を「訓練をまたいで保持する結合」に限る場合、仕様でその結合を列挙する。訓練後、列挙した結合だけを同じ初期状態の新しい実行個体へ移し、残りの状態を初期化して四問を読む。対照では初期結合を移す。二つの割当てで訓練した結合がそれぞれ対応する四問を正解し、初期結合の応答は割当てに依存しないことを予測案とする。移植で成績が崩れれば「指定した結合だけで訓練の効果を再現できる」は外れ。結合と別の状態との協働は未決のまま残る。

## この測定を通過できる反例

固定された比較器が同異を算出し、一個の結合が X/Y の対応を保持する系は、結合を移す試験にも合格する。合格で支持できるのは、指定した結合が未知の四対への対応を運ぶことまで。同異の比較機能の獲得は別の命題とする。失敗から未知の記号対全般の不可能性も導けない。

## Bridge Protocol の監査との対応

本体の bin/eriec-claim-audit.jl の check は TOML の claim record と任意の外部 digest を検査し、出力に evidence_verified=false を明記する。tools/CountermodelAudit.jl の QUERY_PREDICATES には本課題の同異転移の述語がない。このレビューは設計資料の読解と反例による監査。両ツールによる転移の認証として記録しない。

## S 段への引き渡し

claude-lab の仕様では入力符号、保持する結合の範囲、初期化する状態、同点の扱い、二条件で共有するものを明示する。最初の Lean 命題候補は「固定された加算読み出しは四対を厳密に分離できない」。実験予測と対象範囲を正式に凍結してから実行する。
