## 1. 指摘

### R1［high］σ＝0 の点では、世界が世界の種子に依らない。(b) の組がすべて無効になる
- 【事実】生成器は `g_k(t) = clamp(round(M + A·sin(2πt/P + φ_k) + σ·z_k))` で、位相 φ は全種子で同じ（S47:28）。種子が入るのは z だけ。
- 【事実】(b) の組は「別の世界の種子どうし」で、有効な組は「収量の列の食い違う歩の割合が q_min 以上」（S47:60-61）。
- 【推論】σ＝0 では窓 A と窓 B の収量の列が同一で、有効な組は 0 個。PA2 は「σ＝0 の点で過半が先に死ぬ」と予測している（S47:78）ので、予測そのものが判定不能になる。S28 で起きた「介入にならなかった」（README.md:1669）と同じ型。
- 【推論】σ＞0 でも、正弦の成分は全窓で位相が揃っている。供与元の行為は受け手の世界の大きな周期にほぼ合うので、測れるのは「雑音への追従」だけになる。手順 r3 が避けるとした位相の罠が、別の世界の種子を取っても残る。
- 【提案】世界の種子から位相のずれ（0〜P−1 の一様）も引く（既存の PHASE＝(seed−1)×100 と同じ考え、`experiments/eval_grow.jl:19`）。有効な組の基準はそのまま残す。
- 【反証条件】位相をずらしても有効な組の割合が q_min を満たさない点が多ければ、この直しでは足りない。

### R2［high］ORG-FIX は `q`・`sg` を戻すだけでは学習が止まらない
- 【事実】回路の状態 `CState` は `active, q, sg, h, off, t, pend, fresh, prev, cOn, cOff, lastM, lastC` を持つ（`core/circuit.jl:95-102`）。bin3 の対比は `cOn`・`cOff` に溜まる（:185-214）。習慣は `h`（:227・:294）。
- 【事実】S47 の案は「`step!` の後に `q`・`sg` を歩の前の値に戻す」（S47:48）。
- 【推論】`cOn`・`cOff`・`h`・`lastM`・`pend` は更新され続ける。対比が変われば、どの結びつきが駆動するかが変わる。「更新だけを止めた回路」になっていない。
- 【提案】止めるものを列挙して仕様に書く。案は二つ。(i) T0 の状態を丸ごと保存し、毎歩「出力を計算したあと、`active`・`t`・`prev` 以外をすべて T0 の値に戻す」。(ii) 学習の式ごとに止める旗を `step!` に足す（既定オフ）。どちらでも「止めた回路の出力が、同じ入力に対して T0 の回路と同じ規則で出る」ことを関門にする。
- 【反証条件】(i) で戻した回路の行為が、T0 の回路に同じ入力列を与えたときの行為と一致しなければ、止め方が足りない。

### R3［high］YOKE-x の受け手の回路は「起きなかった行為」で学習する。O1 は腕を足さずに解ける
- 【事実】`step!` は答え `d` を回路自身の行為（`onPatch`）から内部で計算する（`core/circuit.jl:174-177`）。S47 の YOKE は「回路を動かし更新もするが、`acting` を供与元の行為で置き換える」（S47:50）。
- 【推論】受け手の回路は、自分が選んだ（実際には行われなかった）行為が答えられたと受け取って確かめを進める。維持する結びつきの数、つまり維持費が、実際には起きていない出来事で決まる。寿命の差に「架空の学習の費用」が混ざる。
- 【提案（O1 の解）】行と列の表にする。窓を n 個取り、**cell(i, j) ＝ 窓 j の身体が、T0 以後、窓 i の ORG の行為の列と維持費の列（維持した結びつきの数）をそのまま受ける**。回路は動かさない。
  - 対角 cell(j, j) は ORG_j そのもの（YOKE-same の関門: 行為・費用・物質の列までビット一致）。`d` は REPLAY と同じ `allocate(offer)` で再計算でき、ORG の `d` と同じ式（`core/body_org.jl:104`、`core/circuit.jl:176-177`）。
  - 統計量 ＝ 対角の平均 − 非対角の平均。世界の厳しさ（列の効果）と供与元の質（行の効果）は、どちらも対角と非対角に同じ回数入るので打ち消す。
  - 帰無の分布 ＝ 行と列の対応づけを並べ替える（並べ替え検定）。「自分の世界に合っていることに意味がない」という帰無のもとで、対応づけは交換できる。RAND・YOKE-x(RAND) の腕は要らなくなり、較正で行為率を凍結する必要もなくなる。
  - 結果の量は「T0＋τ の時点の身体の大きさ（死んでいれば 0）」を主にする。τ は凍結する。供与元が死んだ行は対角が 0 で非対角が正になりうるので、主張に不利な向きに働く（有利な向きの作り物にならない）。打ち切りの規則も要らない。
- 【反証条件】行為も世界も無関係な対照（行為の列を窓の間でかき混ぜた表）で、この統計量が帰無の分布から外れたら、構成が誤っている。これを負の対照として入れる。
- 【留保】この構成が帰無として正しいかは、codex-lab の点検を受けるべき点（前回 defer された論点）。

### R4［med］NONE は格子の世界が始まる前に死ぬ。PA1 は何も測らない
- 【事実】NONE は回路がなく、最初から行為しない。物質は行為でしか入らない（`core/body_org.jl:123-135`）。項番45 では 196 歩で死亡（README.md:545）。格子の世界は T0＝800 から（S47:56）。
- 【推論】NONE は育ちの途中で死に、格子の点によらず同じ結果になる。PA1「全点で ORG より早く死ぬ」は必ず当たる（走らせていないので推論）。
- 【提案】健全性の腕を「T0 まで ORG と同じに育て、T0 から運動を黙らせる」にする。`step!` に黙らせる引数 `sil` がすでにある（`core/circuit.jl:117・130`）。decisions-log #3 の介入 X と同じ形。

### R5［med］K が 1 値では「境」が出ない。K＝2000 は項番46 の再演になる
- 【事実】`cross!` は対の入れ替えで、2 回かけると元に戻る（`core/circuit.jl:24-25`）。K＝2000 では 2000 歩ごとに「入れ替わった期間」と「元の期間」が交代する。
- 【事実】項番46 で GREEDY は入れ替えの 487 歩後に死亡（README.md:558-560）。
- 【推論】入れ替わった期間が 2000 歩あれば、GREEDY は最初の期間でほぼ確実に死ぬ。測れるのは「維持費つきで ORG が入れ替えを生き延びるか」の 1 点で、fable r2 の言う「頻度のどこで学習が維持費を払えるか」の境は引けない。
- 【提案】K を GREEDY の死までの遅れ（約 487 歩）の内と外にまたがせる（例: 短い値を 1 つ足す）。値は二人の合意で。入れ替えの時刻を t＝0 から数えるか T0 から数えるかも書く。

### R6［med］PA3 の文が「検出不能」を当たりに数えている
- 【事実】PA3 は「K＝なしでは ORG は GREEDY より長くは生きない（上積みなし、**または検出不能**）」（S47:79）。指針は「差を検出できなければ予測の成立とはしない」（dev-guidelines.md §1・§2）。
- 【提案】PA3 を「身体の大きさ（副の統計量）で ORG ≤ GREEDY」と「寿命は成立条件を満たす点でだけ判定」に分ける。PA2 の「過半」、PA4 の「大半」にも数の境を置く。

### R7［med］格子の 72 点のうち、別々の点は 56 しかない
- 【事実】σ＝0 では雑音の塊の長さ L が式に効かない（S47:28・36-37）。
- 【推論】σ＝0 の 24 点は 8 通りの世界の 3 重の写しになる（R1 の位相を入れても同じ）。独立な点として数えると、点の数を水増しする。
- 【提案】σ＝0 では L を 1 値にし、点の数を 56 と書く。

### R8［med］SF の候補の維持費が、固定した KC と食い違う
- 【事実】S47 は KC を 0.002 に固定（S47:41、項番81 の値）。法則の候補の SF は「sed_fade＋試行中の維持費 0.0015」（README.md:1430、項番93）。
- 【提案】SF の腕でどちらの値を使うかを書く。数値は変えない規律なので、「候補ごとに記録どおりの値」か「両候補とも 0.002（SF は sed_fade だけを指す）」かを決め、理由を残す。

### R9［low］細部
- 単位の定義: 雑音の種子 s と世界の種子 w を同じ整数にするのか、別に振るのかが書かれていない（S47:19・69-70）。項番81 は一つの seed が雑音・位相・世界を兼ねる（`eval_grow.jl:19`）。
- 「凍結の季節の長期の平均は区画あたり 2.5」（S47:38）は、区画 1 が 2.9、区画 2 が 2.1（`core/body_org.jl:8` から手計算）。平均の平均としては 2.5 だが、非対称。丸めと切り詰めがあるので、軸の M は実現した平均と違う。実現した平均を報告項目に入れる。
- F1「世界の収量は `bo_world` だけで決まる」（S47:10）は言いすぎ。区画への流入は港の残量で頭打ちになる（`core/matter.jl:17-19`、`core/body_org.jl:138`）。物質は保存するので、流入は身体の履歴にも依りうる。実際に頭打ちが起きた歩数を報告項目に入れる。
- 正弦と正規乱数は、Julia と Rust で末尾のビットが違いうる。Rust に写すなら整数の表と整数の雑音にするか、証拠の線は Julia だけと明記する（S47:93）。
- 72 点 × 複数の予測なので、「全体として成功」は宣言しないと書く（S46 と同じ扱い）。
