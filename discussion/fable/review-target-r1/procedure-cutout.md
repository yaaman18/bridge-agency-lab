## 2. P0（関門 J1）

手順書 §4 の J1-1〜J1-8 に、次を足す・直す。

- J1-4 を最初に決める（M2）。
- J1-9（新）主対照の設計は、ラボの実装上の判断として二人が仕様（S 段）で合意して凍結し、J1 で報告する（ユーザーが差し戻せる）。仕様で凍結するもの（往復3 の指摘 2〜6）:
  - 比べるのは同じ窓 B の ORG_B と YOKE-x_B（窓 A の ORG_A の実行された行為の列を再生）。窓の組は「重ならない窓のすべての順序対、重み等しく」を案とし、結果を見て「ずれる窓」を選ばない。
  - 初期状態は同じ、駆動以外の乱数の列は対応させる。
  - 再生の未定義部分: 供与元が死んだあとの行為（案: 休み）、受け手で実行できない行為（案: 効果なし、実行費は規則どおり）、実行費の課金条件。
  - 回路の扱い（案）: YOKE-x の回路は自分の受容器で動き、更新もするが、行為の出力だけを再生の列に差し替える。維持費は自分の回路に同じ規則で課す。費用の列の差を報告し、
    主張は「行為の選び方の差」に限る（回路の止め方が費用・物質を変える直接の効果を外すため、往復3 の指摘 5）。
  - YOKE-same は生存だけでなく、行為・費用・物質の状態の列まで ORG と一致することを確かめる（往復3 の指摘 6）。
- J1-10（新）独立した批判者を誰にするか（M10）。
- 判断票の各行に decisions-log の番号を残す（未記入の 38 件を関門に束ねる）。
- P0 の間に claude-lab が対応表（M1）を `notes/` に書き、codex-lab が点検する（1 日）。

完了の条件: J1-1〜J1-10 のすべてに「決定」か「仮定 H として進める」が付いている。
**仮定 H で代えられないもの**（往復3 の指摘 9）: 宿主とセンサーの許可（J1-4）、既定の規則・数値の変更、法則の凍結（J2）、切り出し（J3）。これらはユーザーの決定を待つ。仮定 H は bridge-protocol の理論に触れる点（J1-1・J1-3 など）にだけ使う。

## 3. P-pre 既存の世界での H-E3b（M5、新しい試算。J1-9 の仕様を二人で合意して凍結したあとに走らせる）

- 目的: 実測の記録を待たずに、H-E3b の比較（ORG 対 YOKE-x 対 NONE、GREEDY は別）が成り立つ設計かを確かめる。既存の世界（凍結の季節・無作為の世界、項番81 の設定）で走らせる。
- 予測と反証条件を先に凍結する。先例（項番81）から、無作為の世界では ORG の生存が低いことを予測に入れる。項番81 の「維持費が原因」は推論で、費用を揃えた比較では確かめていない（codex 往復2 の指摘 1）。
- 同じ窓で行為列を再生する写し（YOKE-same）を負の対照に入れる: ORG と生存だけでなく行為・費用・物質の状態の列まで一致すること（実装の整合の確認。列が一つでも違えば不合格、codex 往復3 の確認 4）。一致しなければ実装を直すまで先に進まない。
- 結果の扱い: 同じ窓の中で YOKE-x が ORG より早く死ぬなら、P3-0 でも同じ設計を使う。差がなければ、その世界での「状態に応じた選択の利益」は支持されないと記録し、P3-0 の予測に反映する（設計は変えない）。
