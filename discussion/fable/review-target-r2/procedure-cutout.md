## 5. P-pre 既存の世界での (b)(c)（新しい試算）

- 目的: 実測の記録を待たずに、(b)(c) の比較の設計が成り立つかを確かめ、P3 の統計量・最小の単位数・有効な組の基準を決める材料を得る。**P-pre の結果は実測の世界での主張の証拠には使わない**（設計にだけ使う）。
- 前提: J1-9 の仕様（S 段、二人の合意）を凍結し、U3 の条件（批判者の閲読・異論の記録・採否と理由の回答）が済んだ後に走らせる。煙の走りも凍結してから。
- 世界: 凍結の季節と無作為の世界（項番81 の設定）。腕:

| 腕 | 中身 | 役目 |
|---|---|---|
| ORG | 回路が自分の受容器で選んで行為する | 基準 |
| YOKE-x(ORG) | 同じ窓 B で、別の窓 A の ORG_A の実行された行為の列を再生 | H-E3b |
| OPEN | 状態に依らない固定の予定で行為する | 帰無の基準 |
| YOKE-x(OPEN) | 窓 B で、窓 A の OPEN の行為の列を再生 | 帰無（OPEN と差が出ないはず） |
| YOKE-same | 同じ窓で ORG の列を再生 | 実装の整合（行為・費用・物質の状態の列まで ORG と一致。一つでも違えば不合格で先に進まない） |
| NONE | 回路を黙らせ、行為しない | H-E3a（健全性） |
| GREEDY | 同じ受容器を読む固定の規則（項番46） | H-E3c |
| REVR（ORG と GREEDY に） | 途中で受容器の意味を入れ替える（項番46） | 見落とし 1 の安い確認 |

- 仕様で凍結するもの: 窓の組（重ならない窓の順序対、重み等しく、有効な組は駆動の列どうしの距離で先に決め、除外は入力の列だけで）、初期状態、駆動以外の乱数の対応、
  再生の未定義部分（供与元の死後は列が尽きる→**比較は供与元の死で打ち切る**、受け手で実行できない行為は効果なし・実行費は規則どおり）、
  YOKE の回路の扱い（自分の受容器で動き更新もするが、行為の出力だけを列に差し替える。維持費は自分の回路に同じ規則。費用の列の差を報告）、判定時点・統計量・境・最小の単位数、
  打ち切りの細部（両方が生き残る組、同時の死、打ち切りの時刻ちょうどの死）、**報告項目**（実行できなかった行為の割合・実効の行為数・取得量・費用の差。差の源として残る代替の説明を測る、指針 §2）。
  推定の対象は打ち切った区間の中に限り、全寿命へ一般化しない。主張は「状態に適合した行為選択全体の利益」まで。
- 予測の向き（凍結の候補）: (b) 凍結の季節では YOKE-x(ORG) が打ち切り区間内で先に死ぬ組が多い。(c) 受容器の意味が変わらない世界では ORG は GREEDY より長くは生きない（主に項番81。項番46 は身体の大きさの差で寿命の証拠ではない）。(c) の判定は三つ（長い＝外れ／短い＝向きどおり／検出不能＝成立にしない）。REVR では ORG が GREEDY より長く生きる（項番46 F2〜F4）。
- 結果の使い方: 分散から P3 の記録の長さと最小の単位数を決める。有効な組の基準が働くかを確かめる。YOKE-x(OPEN) に差が出たら、打ち切りや再生の処理だけで差が出る設計なので、H-E3b の設計を作り直して P3-0 に進まない。

## 9. P4 書き込みの道を閉じる（P3-3 と同時）

**許可した経路の一覧**（経路・操作者・権限）を先に書き、それ以外が塞がっていることを並走の写しで試す。

| 経路 | 塞ぎ方 | 試し方 |
|---|---|---|
| 実行形式の差し替え | タグを打ったコミットから作り sha を記録、更新の仕組みを置かない | 別の実行形式に替えようとして失敗する |
| 状態ファイルへの書き込み | 専用の利用者の持ち物にし、エージェントの席にもユーザーの普段の席にも権限を渡さない | claude-lab・codex-lab の席から書こうとして失敗する |
| 入力の経路 | 作者が随意に動かせる信号を収量に結ばない（J1-5） | 信号の経路に作者の操作点がないことを配線と設定で確かめる |
| 壊れた状態の修復 | 直さない。壊れを検出したら止まる（P1-7） | 壊した写しが止まり、誰も直せない |
| 宿主の再起動 | J1-3 で宣言した自動の再開だけ | 電源を落として戻し、宣言どおりに再開する |
| 選抜 | 結果から選ばない（P3-4） | 種子を引く手順の凍結の時刻が切り出しより前 |

- 観察は一方通行: 個体が追記だけの記録を外へ出し、観察する側は写しを読む。通訳（LLM の語り）は読み取り専用。解析の手順と予測は切り出しの前に凍結する。
- 凍結の先行時刻は sha だけでなく、agmsg の送信時刻（db の記録）と decisions-log の記載で示す。
- codex-lab は §12 の点検表で隠れた救出の経路を敵対的に探す。CLAUDE.md・AGENTS.md に、切り出した個体の宿主と状態の場所を触れてはいけない対象として書く案を出す（書き換えはユーザーの承認後）。
- 宿主の機械の保守（部品の交換）を世界の出来事とみるか救出とみるかは、J3 の前にユーザーが決める。保守的な読みは「状態には触れない。宿主が失われたら個体の死」。

完了の条件: 表の試しがすべて「失敗する」で揃い、codex-lab の探索で新しい経路が見つからない。

## 10. P5 切り出し（関門 J3）と P6 切り出したあと

- ユーザーが確かめる三条件（promise-cutout.md §4）: その法則のままで一生が終わってもよい／死んでも救わない／状態に書き込む道が閉じている（P4 の記録）。
- 揃ったら: (1) claude-lab が切り出しの記録の下書き（法則のコミットと実行形式の sha、写像の sha、種子を引く手順の sha、時間の扱い、宿主、J1〜J3 の決定の番号）
  (2) codex-lab が凍結した各ファイルの sha と照らす (3) ユーザーが日付を入れ、種子を引き、自分の手で起動する (4) ユーザーが起動に使った権限を手放す。エージェントは起動の操作をしない。
- 切り出したあと: 二人は研究を写しと別の変種で続け、外へ出た記録の写しを凍結した手順で読む。切り出した個体の宿主・状態・法則に触れない、生き残るように世界の側を変えない。
  ユーザーも同じ（約束を変えられるのはユーザーだけ）。早く死んでも手順の失敗ではない。記録を残し、何もしない。

## 11. 臨界経路に載せないもの（席が空いたときだけ、3 手に 1 手まで）

L2 の頑健化（交互の並びの機序、G1 の下での T_NM）、項番86 の設定の種子の診断（J1-2 で SF を候補に残すなら P3-0 の前に済ませる）、L3R の接続（G16・G19）、BP2・BP3、快・不快の層、
README の分割、S45b（公式 TRM、ユーザーのセットアップ待ち）。

## 12. 回し方と点検表

- 臨界経路を先に取る。STATE に二本の待ち行列を書き、待ちの間に進められる段を一つ挙げる。判断票は関門ごとに一枚。J2 のあとの臨界経路の上での規則・数値・写像の変更は codex-lab が BLOCK。煮詰まったら fable-lab に 1 回。
- 救出の経路の点検表（codex-lab、仕様と差分のレビューのたび）:
  - [ ] 結果を見てから選ばれたものがないか（法則の候補、育ち、種子、写像、信号、窓、有効な組）
  - [ ] 許可した経路の一覧にない、個体の外から状態に届く引数・ファイル・環境変数・時刻の読みがないか
  - [ ] 作者が動かせる量が、収量か生死の判定に届いていないか
  - [ ] 再開・修復・移行のコードが、宣言した自動の再開の範囲を超えていないか
  - [ ] 反復の数を独立な反復として数えていないか（対象集団の節と照らす）
  - [ ] 予測の凍結（煙を含む）が走らせた時刻より前か（sha・agmsg の時刻・decisions-log）
- claude-lab の報告は段ごとに事実・推論・提案を分け、E1〜E5 のどれが動いたかを一行で添える。

## 13. 中止・後戻り

| 起きたこと | すること |
|---|---|
| P-pre で YOKE-same が整合しない、または YOKE-x(OPEN) に差が出る | H-E3b の設計を作り直す。P3-0 に進まない |
| H-E3b 不成立 | 止めて報告。ユーザーが選ぶ |
| 世界の厳しさを決め直す（ユーザーが選んだとき、一度だけ） | 探索として記録し、決め直しの規則を先に凍結、**新しい保留の窓**を取る。使った窓は確認に使わない |
| 信号が質の基準を満たさない | 信号を選び直す（上限 2 回）。写像の作り直しで合わせない |
| Julia と Rust がビット一致しない | P4 に進まない。原因を直すまで並走も始めない |
| J2 のあとに規則か数値を変えたくなった | ユーザーの決定として記録し、P3-2 からやり直す（保留の窓は新しく） |
| P4 の試しで書き込みが通った | 並走の写しで塞ぎ、表の試しを全部やり直す |
| 切り出したあとに不具合が見つかった | 何もしない。記録に残し、次の変種で直す |

この手順の反証条件: P-pre で、有効な組の基準を満たす窓の組が事前に決められない（どの組でも駆動の列のずれが測れない）なら、実測の駆動で H-E3b は測れない。そのときは P2 の構成から作り直す。
