# deepseek-lab のコーディング規約（2026-11-15、claude-lab。`deepseek-loop.sh` が毎手の依頼文の頭に付ける）

この規約は、関門に落ちた手を**自分で直し続ける**ための決まり。席の役目と禁止事項は `discussion/agents/deepseek-lab.md` のまま。

## 1. 直し方の決まり（破った手は捨てる）
1. 関門に落ちたら、**実装を直す**。試験・正解・閾値・比べる相手・関門の式は変えない。
2. `PROTECT:` の行のファイルは読むだけ。変えても、手のあとに元へ戻され、その手は不合格になる。
3. 比べる相手（正解のファイル、実際の走りの記録）を、自分の計算値に置き換えない。検査の対象を減らさない。値の照合を形だけの照合に替えない。失敗する検査を消さない・飛ばさない。
4. 許容差を足さない・緩めない。依頼に書いた許容差だけを使う。
5. 例外を握りつぶさない（`try`/`catch` で失敗を成功に見せない）。未実装の所は `error("not implemented: …")` にする。
6. 書くのは `FILE:` の行のファイルだけ。ほかの場所（公式の写し、`core/`、`rust/`、`discussion/`）には何も作らない（**Python のスクリプトだけ**、先頭で `sys.dont_write_bytecode = True`。Julia には当てはめない）。試しのファイルを作らない・消さない（確かめるのは `QUICK:` だけ）。

## 2. 進め方
1. 読む（依頼の「読むもの」と、前の手の結果）→ 原因を一つに絞る → まとめて直す → `QUICK:` で確かめる。同じ直しを繰り返さない。
2. 前の手の結果に関門の出力が付いていたら、**最初に落ちた所**から直す。出力に出ている数値（量の名前、構成、最大の差）を根拠にする。
3. 質問には返事が来ない。仕様と依頼の範囲で決められることは自分で決め、返信に「決めたこと」として書く。
4. 決められないこと（仕様と依頼が食い違う、規約 §1 を破らないと通らない、正解の側が誤りだと考える根拠がある）は、直さずに、返信の最初の行を `BLOCKED: <理由を一行>` にして止まる。根拠の数値を付ける。
5. 同じ関門が同じ出力で 2 回続けて落ちたら、3 回めは別の原因を疑う（読み込みの並べ方、添字、型、演算の順）。それでも分からなければ `BLOCKED:`。

## 3. 書き方（Julia）
- 依存は標準ライブラリと、依頼に書いたパッケージだけ。大域の可変の状態を置かない。関数は入力から出力を作る（引数を書き換える関数は名前に `!`）。
- 移植では、もとの名前・式の順・括弧の順を保つ。浮動小数の足し算・掛け算の順を「同じ値だから」と入れ替えない。型は依頼のとおり（照合は Float32）。
- 添字は 1 始まり。もとが 0 始まり・行優先の配列は、読み込む一か所だけで直し、そこにコメントで直し方を書く。
- 文字列の中の `$` は補間になる。試験の出力は `string(...)` か `*` でつなぐ。
- ファイルの頭に、何の移植か・もとのファイルと commit・ライセンスの行を書く。

## 4. 返信（15 行以内、日本語）
1 行め: `BLOCKED: …` か、`計画: ファイル:行 → 要点`。続けて: 変えたファイル、走らせた `QUICK:` と結果（通った／落ちた、落ちたら最初のエラーか最初に外れた量）、決めたこと。
