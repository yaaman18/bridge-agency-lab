## 1. 目的（稽古で洗い出すもの）
- 長く走らせたときの機械の側の不具合: 電源、microSD の書き込み、熱、時計なしでの動作。
- 停止と再開の実際: ユーザーが Pi を運ぶ・電源が切れる → 止まった歩から続くか、監査の記録に何が残るか（終わらなかった歩、不明の停止）。
- Mac の基準との並走: 同じ個体・同じ入力を Mac で（間隔なしで）先に計算しておき、Pi の各歩の保存の SHA が一致し続けるか。

## 2. 決めること（下書きの案。S-R とユーザーの確認で確定）
- 個体: 法則は未決（J1-2）なので、**試-1＝L2、試-2＝L2+SF の二体を並べる**か、一体にするか。案: 二体（別々の走りのファイル）。
- 誕生の種子と入力: 新しい種子（657 は S53 の次の段に仮に取ってあるので、ここは 669〜 を案とする。台帳で確かめる）。入力は項番155 の生成器（P＝1000、σ＝1、L＝300、M＝2.5、入れ替えなし）で作った**有限のファイル**（7 日ぶん＝60480 行）。終わりのない入力の源はまだないので、尽きたら稽古は終わり。育ちの扱いは S48・S49 の照合の体と同じにする。
- 再開: Pi の起動時に、凍結した手順だけで自動で再開する常駐（H5 の「裁量のない自動の再開」の稽古）。再開のとき、入力のファイルの何行めから与えるかを走りのファイルの n から決める包みが要る。**この包みは、状態を読んで入力を選ぶ経路**なので、P4 の経路の表に載せる対象として明記する（n 以外を読まないこと、入力の中身を変えないことを検査する）。
- 止め方: ユーザーはいつでも電源を切ってよい。claude-lab は止めない・状態に書かない。稽古を終えるのはユーザーの一言。

## 3. 予測の案（凍結はレビューの後）
- PT1 一致: Pi の監査の commit の SHA が、Mac の基準の同じ歩の SHA と全歩で一致（食い違いは最初の歩を報告）。
- PT2 間隔: 連続する二歩の間は 10 秒以上（測るのは Mac の側。Pi の時計は使わない）。
- PT3 停止と再開: 電源を切って入れ直した回数（ユーザーの記録）と、監査の「end・error のない停止」の数が合う。再開の後の SHA は基準と一致し続ける。終わらなかった歩は起きなかった歩として捨てられ、状態は進まない。
- PT4 機械: 7 日のあいだ throttled＝0x0、書き込みの誤りなし。外れたら、その事実が稽古の成果。
- 個体が 7 日生きるかどうかは予測しない（法則と世界で決まり、この稽古の問いではない）。死んだら死んだと記録する。死んだ後も同じ間隔で入力を消費し続けること（S49c §1）を確かめる。

## 4. 未決の問い（ユーザーへ）
- 一体か二体か。入力の世界（上の案でよいか）。7 日でよいか。稽古のあいだに Pi を運んでよいか（運んでよい。電源が切れるのは稽古の対象）。
