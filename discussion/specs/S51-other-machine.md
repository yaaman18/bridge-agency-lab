- 出どころ: ユーザー 2026-11-14「ネットワークはAでいいや。そして照合を初めて」（Pi 5 を Mac に直結、インターネットなし）。項番158・160 の限定「この機械だけ」を一台ぶん外す。`notes/D-OPEN.md` §6.4 の段 1 の前提（別の機械での一致）。
- 位置づけ: 系統の側の照合。**個体の切り出しではない。** Pi に個体を置く決定もしない。新しい規則・数値・種子はない。

## 1. 機械
- 基準: Mac（x86_64-apple-darwin）。相手: Raspberry Pi 5 Model B Rev 1.0（Cortex-A76、aarch64、Debian 13、microSD）。直結の LAN で SSH。Pi にインターネットはなく、時計は合っていない（個体は時刻を読まないので照合には使わない）。

## 2. 実行物
- ソースは commit d5a7f6d（S49b の版。`rust/being-core` の 4 ファイルの sha は `freeze-rust-onelife-b-code.txt` の参照の値）を `git archive` で作業の外へ取り出したもの。作業中の木（S49c の試験が走っている）には触れない。
- Pi 用: Mac の上で `aarch64-unknown-linux-musl` へクロスコンパイル（静的リンク、リンカは rust-lld、release）。Mac 用: 同じ取り出したソースを release でビルド。**Pi の上ではコンパイルしない。**
- 入力のファイル（駆動列 D1・D3、`core/check/out/math-v8.txt`）は Mac で作ったものを Pi へ写す。sha を両側で確かめる。

## 5. 関門
- F: 仕様と予測の sha が `experiments/freeze-other-machine.txt` にある。
- M0: 取り出したソースの being-core 4 ファイルと `onelife-run.rs` の sha が凍結の値と同じ。両ビルドとも警告 0。Pi のバイナリが aarch64 の静的な ELF であること。
- M1: 写した入力ファイルの sha が両側で同じ。**Pi 用の実行物（ELF）の sha も、Mac で写す前と Pi で写した後で同じ**（codex 命題4）。
- M2（負の対照）: 照合の道具が違いを捕えること ― Pi 側の出力の 1 バイトを変えた写しを「不一致」と報告する。法則を取り違えた走り（L2 の代わりに L2+SF）を「不一致」と報告する。

## 6. 言えること・言えないこと
- 言える: この Mac とこの Pi 5 の一台ずつ、**Mac でクロスビルドしたこの特定の ELF** について、この 8 体の全歩の状態の SHA-256 が一致する／しない（SHA の衝突がないことを前提。状態の中身そのものを比べるのは点の保存だけ）。「別の CPU の上で同じ状態遷移を実行した一致」まで（codex 命題2・7）。
- 言えない: Pi の上でコンパイルした実行物・道具の持ち運び。ほかの ARM の機械・ほかの OS・ほかのコンパイラの版・glibc のビルド。停電への耐性。長い時間の走りでの機械の誤り。Julia を Pi で走らせた場合。
- Julia との関係: Mac の Rust は S49 の PR1 で Julia の基準と全歩一致している（同じ 8 体・同じ N）。Pi と Julia の直接の比較は、`core/check/out` に Julia の基準がある 2 体（627・D3・3000 歩）だけ行う。残りは Mac の Rust を介した推移。

## 6b. PM3・PM4 の操作と呼び方（codex 命題3・5）
- PM4 は「保存の形式と再開の、機械の間の互換性」の照合。操作者が走りのファイルの写しを取って別の機械で続ける**照合のための介入**であり、個体の自律した移動でも、個体を置くことでも、切り出しでもない。切り出した個体でこれを行えば H5 の「介入」に当たる。
- PM3・PM4 の中断は、**n＝2000 の走りのファイルが書かれたのを `onelife-info` で見てから** SIGKILL する（入力は 2000 行だけを与えて書き終わりを待ち、その後に止める）。SIGKILL と通常の終了の試験は fsync と停電への耐性を確かめない。
