## 2. 1 歩の順序（S66 §2・S67 §2・S68 §3 を一本にした読み。ずれたら元の仕様が正）

## 3. 関門（すべて合成重みとフィクスチャで、C0 に依存しない）
- **U1（写しの一致）**: 引き込みなし・Null 予測器のとき、`aue_step` の状態列が `onelife_step`（core）と**全歩ビット一致**（種子 690101・690102、各 2000 歩、L2 と L2+SF）。負対照: 写しに 1 箇所だけ丸めを変えると不一致を検出する。
- **U2（未来漏れゼロ）**: y[t]・Y_t を反転しても、当歩の p_t・ê_t・π_t・a_t はビット一致（合成重み、各 25 例）。負対照 LEAK で不一致。
- **U3（再生）**: 記録した `input` 行だけから `aue_step` を再実行して、全歩の commit 行と最終 `run` の SHA が一致（2000 歩）。1 行を書き換えた負対照で最初に壊れた歩を検出。
- **U4（再開）**: 歩 k の `run` から再開した列が、通しの列と全歩ビット一致（k = 0, 1, 777, 1999）。終わらなかった歩の入力は同じ行がもう一度与えられる（S54 の規則）。
- **U5（2 プロセス決定性）**: 別プロセス 2 回で `results` と最終 `run` の SHA が一致。FMA・スレッド数・BLAS の影響を受けない（1 スレッドと 8 スレッドで比較）。
- **U6（境界）**: S62b 型の未申告書込 0 件、RNG 違反 0 件（変種が `core/`・pool に触れない）。`sh core/check/run.sh` exit 0、`~/bridge-protocol` 差分 0。
- **U8（誤配線の検出、codex P1）**: DET の行為と π の抽選結果が異なり、身体の応答も行為で分かれる固定例（合成フィクスチャ）で、S66 から**独立に手計算**した行為・応答・次状態と一致。「π で引いた行為を記録するが身体には DET の行為を渡す」変種が不合格になる負対照を置く。
- **U9（会計順、codex P4）**: 維持費の引落しの前後で生死判定が分かれる境界例を置き、S67 §2 から手計算した残高・生死・頭更新の有無と一致。引落し順を逆にした変種が不合格になる負対照。
- **U10（死亡、codex P5）**: (a) 生存から死亡する歩: 最終状態・頭・commit 件数を正本と照合。(b) その直後の呼出し: 読むと失敗する drive を与え、「drive 読取 0、commit 0」を直接検査。
- **U11（stale、codex P6）**: 直前の有効入力と区別できる stale 行を与え、当歩の drive・窓・頭の扱いを S68 の期待値と照合。`stale_flag` を無視する変種が不合格になる負対照。
- **U7（予算）**: `TRM_B_LOW`（H_max=3）で完了巡数が全歩で 3。0 巡フォールバックの出力が有限。

## 4. 事前予測（走らせる前に凍結。外れたら外れたと報告）
- **P-S69-1**: U1〜U11 は初回の実装で全部は通らない。**初回の走りで少なくとも 1 つの関門が不合格になる**。「初回」は、凍結後の同一実装で全関門を最後まで評価した一式と定義し、未実行は未判定とする（理由: 写しと配線は新規で、S49d・S57 でも初回に外した前例がある）。外れ＝初回から全合格。
