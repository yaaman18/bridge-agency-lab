## 1. 目的・S62 からの厳格な差分・非目標
- **目的**: S62（項番178）で正本 AUE（`core/one_life.jl` `LawL2`・`core/matter.jl`、無変更）の主要境界性質が確認された一方、**テスト側フィクスチャの初期値前提ミス 2 点**（GB2(5) `pool[1]` 上限飽和＋`paid` 返却、GB4c `pool=3U` での歩 $t$ 引出）により GB2・GB4 が不通過（`P-S62-2`・`P-S62-4` 外れ）となった。本 S62b は **`core/` を一切変更せず、上記 2 サブフィクスチャの初期条件のみを `core/one_life.jl`・`core/circuit.jl` の厳密算術境界に基づいて再設計**し、新種子 20 件で B-Test 1〜4 全関門（GB1〜GB5）が同時に成立するかを検証する。
- **S62 r2 からの厳格な差分（これ以外の起点 $s_{40}$・閉包定義・`live_wrapped`・GB1・GB3・GB4a・GB4c 区別対・GB5 はすべて S62 r2 と 100% 同一）**:
  1. **GB2(5) ポート成分の最小性フィクスチャ（低貯留＋非飽和プール）**:
     - `s_40` のディープコピー上で **`pool = [0.0, 0.0]`** に揃え（`50U = 1.00` への溢れ返却を排除）、駆動 **`g = (5, 5)`**（総要求量 $10U = 0.20$）で 1 歩進めたとき、
       - 腕 A：`w.port.reservoir = 0.00`
       - 腕 B：`w.port.reservoir = 0.25`
     - 事前算術確認（`core/circuit.jl`・`core/one_life.jl:57-74`）：空プールでは回路引出も溢れ返却もなく、`newborn(false)` の辺総数 22 より支払総額 $\mathrm{paid}_{\mathrm{all}} \le 0.002 \cdot 22 + 0.004 \cdot 2 = 0.052$。よって腕 A の総供給は $\le 0.052 < 0.20$（`k=1` が全額取り `k=2` は 0）、腕 B は $\ge 0.25 > 0.20$ より `[0.10, 0.10]`（和 `0.20`）。判定は `pool_A != pool_B` かつ `mu_A != mu_B`（20/20、実測 `paid_all`・`pool_41` 差は診断出力）。
  2. **GB4c 身体翻訳同一視対フィクスチャ（`y` 上限 5 飽和＋非溢れ中間域）**:
     - `s_40` のディープコピー上で **`pool = [0.40, 0.40]`（$= 20U$）** に揃え、歩 $t$ に `g_t = (4, 4)` vs `(5, 5)`、歩 $t+1$ に同一駆動 `g_{t+1} = g_sched(41)`（$=(5, 1)$）を入れて 2 歩進める。
     - 事前算術確認（`core/one_life.jl:34,52,64,73`・`core/circuit.jl:8,108`）：
       - **貯留槽下限**: 正規の `s_40` は初期 `w.port.reservoir = 300.0` から 40 歩進めた状態であり、1 歩の `port_take!` 上限は $(5+5)U = 0.20$（`g_sched` 実値は $(5+1)U = 0.12$）なので、`s_40` 時点の貯留槽は $\ge 300.0 - 40 \cdot 0.20 = 292.0 \gg 0.20$、歩 $t+1$ 時点でも $\ge 291.8 \gg 0.12$（各評価種子で実測下限も確認）。よって歩 $t$・歩 $t+1$ とも `port_take!` は貯留不足クランプを起こさず満額供給される。
       - **歩 $t \to t+1$**: `allocate` の総上限 `P_CAPACITY = 5` より歩 $t$ の回路引出は合計 $\le 5U = 0.10$。歩 $t$ 終了時の `pool_{t+1}[k]` は腕 `(4,4)` で $0.40 - \mathrm{take}_k + 0.08 \in [0.38, 0.48]$、腕 `(5,5)` で $0.40 - \mathrm{take}_k + 0.10 \in [0.40, 0.50]$。両腕とも $\ge 5U = 0.10$ なので歩 $t+1$ 頭の `y_{t+1} == [5.0, 5.0]` が一致し、かつ $< 50U = 1.00$（溢れなし）なので `pool_{t+1}^{(4,4)} != pool_{t+1}^{(5,5)}`（Float64 判定は `!=`、差分値は参考出力）。
       - **歩 $t+1 \to t+2$**: 歩 $t$ の `step!(circuit, ...)` は同一入力から走るため `circuit_{t+1}`・`noise_{t+1}` がビット一致し、`y_{t+1}` も一致するため歩 $t+1$ の回路出力 `out_{t+1}`（`acting_c, d_c`）および `circuit_{t+2}` はビット一致する。さらに `pool_{t+1}[k] >= 0.38 > 0.10 = 5U >= d_{t+1}[k] * U` かつ `pool_{t+1}[k] + g_{t+1}[k]*U <= 0.50 + 0.10 = 0.60 < 1.00 = 50U` なので、歩 $t+1$ の引出量も供給量も両腕で同一（非飽和・非溢れ）となり、`pool_{t+2}^{(4,4)} != pool_{t+2}^{(5,5)}`（よって $\mu_{t+2}$ 不一致）が残存する。
  3. **GB4b 符号付き勝敗基準の明文化**:
     - `Δ_taken = taken_live - taken_yoke` と `Δ_B = B_live - B_yoke` について、(i) RNG 遷移一致 `400/400`、(ii) 非ゼロ差（`Δ_taken != 0 || Δ_B != 0`）が過半数（$\ge 11/20$）、**(iii) 符号付き Live 優位（`count(Δ_taken > 0) > count(Δ_taken < 0)` かつ `count(Δ_B > 0) > count(Δ_B < 0)`）** を GB4b の合否条件として明記する（20/20 で Yoke が勝った場合に誤って合格しないようにする）。
  4. **監査互換**: `run_gates.jl` は `--readonly` フラグを備え、`core/*.jl` 9 ファイルおよび親 S62 ファイル（`experiments/boundary_audit/BoundaryAudit.jl`, `run_gates.jl`）の非変更検証を `SHA.sha256` のみで行う（`git` 非呼び出し）。
- **非目標**: `core/`・`rust/`・`formal/`・`experiments/boundary_audit/`・`~/bridge-protocol` の変更、`phenomenal_claim` の主張、GB1 の BP 側正本昇格（BP 側正本化は BP7/BP9 案件）。
