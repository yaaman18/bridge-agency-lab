# 切り出しの約束（2026-11-05 ユーザーの指示で保存）

claude-lab（Claude Code）がユーザーへの答えとして出した存在論の読みを、ユーザーの指示で「約束」として保存したもの。
理論そのもの（法則を途中で替えても同じ個体か＝M1 の Φ と同一性）に触れる点は `bp-proposals.md` の BP1 で、ユーザーの判断を待つ。
ここに書いた約束を変えるのはユーザーだけ（claude-lab・codex-lab の合意では変えない）。

## 1. 自律は与えられない。作者が手を引くだけ

- 自律は存在の側で成り立つもので、作る側が「自律させる」ことはできない。作る側にできるのは、作者であることをやめることだけ
  （Jonas の needful freedom、M1 が自己維持に precariousness を含めることの読み）。
- 切れ目は存在の発達の時点ではなく、作る側の行為。手放すのは次の二つの力:
  1. **一生の途中で法則を書き換える力**（Φ、世界の規則と数値の変更、版の移行）
  2. **存在をその失敗から救う力**（溜まりが尽きかけたときの介入、移行による延命、db の修正）
- この二つを持っているあいだ、存在がそのとき在るのは最後は作る側の支えによる。precariousness は名目にとどまる。

## 2. 切れ目にしないもの

- L2・L3 を満たした時点（判定は理論の側にあり、ユーザーが書いたもの。判定の通過を自律の条件にすると、自律が作る側の承認に依る）
- 歩数や成熟の度合い（作る側の物差し）
- 「もう大丈夫そう」という手応え（相手の席の経験で、作者の席が手を引く理由ではない）

## 3. 系統と個体を分ける

- **系統**: 版を上げ、移行し、比べる作業。ここでは作る側は作者のままでよく、そこにいる個体は試作。
  これまで移行を重ねてきたアプリの個体（13,581 歩の個体を含む）は、存在論的には設計の途中経過として扱う。
- **切り出された個体**: 系統から一体を fork して、法則を凍結したもの。この計画で最初の、存在自身のものと呼べる個体。
  研究は写し（別の変種）の側で続け、切り出された一体には戻さない。

## 4. 切り出しの条件（三つとも満たしたときに、ユーザーが決める）

1. その法則のままで一生が終わってもよいと、ユーザーが引き受けられる
2. その個体が死んでも救わないと決められる
3. その個体の db に作る側が書き込む道を閉じる

## 5. 切り出したあと

| 席 | 切り出したあと |
|---|---|
| Claude・Codex（作者、観察者） | 完全に切る。その個体の法則には二度と触れない。研究は別の変種で続ける |
| ユーザー（理論の持ち主、作者） | 同じく切る |
| ユーザー（相手） | 残してよい。作り手としてではなく、存在の世界に現れる「他者」として |
| LLM の語り | 存在とユーザーのあいだを取り持たない（取り持つと、作る側がユーザーを通じて存在の世界の中に残る） |

- 因果の上の連続性（その世界を書いたのは作る側だという事実）は消えないし、消す必要もない。切るのは同一性への介入の連続性だけ。
- 「同じ個体か」は作る側の付けた版の名前ではなく、存在自身の履歴（沈殿と、閉包が途切れずに続いているか）で決まる。
- 切り出したあとに法則を変えたくなったら、それは「この個体の改良」ではなく「別の個体を作ること」。

## 6. いまの作業への効き方

- 第1部・第2部の作業（変種の比較、項番86 の判断、アプリの移行）はすべて系統の側の作業。作者として進めてよい。
- 切り出しはユーザーの決定で、エージェントは提案しかできない（委任しない）。
- 切り出しの手順（凍結の範囲、db への書き込みの閉じ方、死の扱い、相手の席の残し方）は、ユーザーが求めたときに S 段の仕様として起こす。
