## 1. 証拠の線（S47 r2）

**K1 (b) は ORG に固有の証拠にならない。GREEDY の行×列の表を参照に足す。**
- 【事実】REPLAY-x cell(i, j) は、窓 j の世界で窓 i の ORG の行為の列を再生する（S47 §4）。世界の位相 θ_u は窓ごとに違う（S47 §3）。GREEDY も受容器を読んで行為を選ぶ（`core/body_org.jl:106-110`）。
- 【推論】世界に結びついた行為の選び方なら何でも、位相のずれた他の窓の列より自分の列のほうが合う。σ＝0 の周期の世界で D＞0 が出るのは、ほぼ作りから従う（PA2 は外れにくい）。同じ表を GREEDY の行為の列で作れば、同じく D＞0 になるはず。
- 【提案】GREEDY の行×列の表（供与元 GREEDY_i、受け手は T0 以後その列を再生、維持費 4 本）を参照として足し、D_ORG と D_GREEDY を並べて報告する。(b) で言えるのは「行為が自分の窓の世界に結びついている」までで、「学習した回路の選び方に固有の利益」とは言わない、と §5 に書く。
- 【反証】D_GREEDY が検出不能で D_ORG だけ成立する点が過半なら、(b) は固定の反射にない何かを測っている（この指摘は外れ）。

**K2 (c) の K＝なしは、比べる前から向きが決まっている。知らないのは K＞0 だけ。**
- 【事実】GREEDY の維持費は 4 本ぶん固定（:112-116）、読む受容器 r7・r8・r1・r2 は作者が世界を知って選んだもの。ORG が保つ結びつきは約 14 本で半分近くは確かさ 0 の沈殿だけ（項番83）。GREEDY に同じ負担 KC 0.0065 を課すと 1/10（項番83）。
- 【推論】K＝なしの 20 点の PA3（上積みあり 0 点）は、項番81・83 の言い直しで、得るものが少ない。40 点（K＝なしの 20 ＋ 対応する ORG-FIX）は「既知の確認」に走りの量の 1/3 を使う。
- 【推論】学習が勝ちうる K＞0 は、U6 で切り出す個体の世界から外してある。つまり個体の世界では (c) は作りの上で「回路は荷」と予測される。これは U1 が認めている。P-A の (c) は個体の線の判断を何も変えない。
- 【提案】(c) に費用をそろえた参照を一本足す: GREEDY-KC（GREEDY に、同じ窓の ORG の維持した数の列と同じ維持費を払わせる）。ORG 対 GREEDY-KC は「同じ費用のもとでの選び方の差」に近づく（項番83 の対照の格子版）。これがないと (c) は「14 本と 4 本の差」を測るだけ。

**K3 P-A の結果ごとに「何を変えるか」を凍結文に入れる。変えないなら格子を削る。**
- 【事実】合成の結果は現実の主張の証拠に使わない（S47 冒頭）。(b)(c) は切り出しの条件にしない（J1-11）。P-A の使い道は、段階 B の設計（統計量・単位数・記録の長さ）と JB の材料（手順 r3 §5）。
- 【推論】いまの S47 には、どの結果が出たら段階 B の何が変わるかの表がない。どの結果でも次の手が同じなら、41,760 本（60 点 × 2 法則 × 348 本、Q5）は判断に効かない。
- 【提案】§7 に「結果 → 段階 B・JB で変わるもの」の表を足して一緒に凍結する。表に効かない軸は削る。削る案（結果を見る前の決定）: P は 1000 だけ、L は 300 だけ（σ∈{0,1,2}）、M 2 値、K 3 値 → 18 点。P＝250・L＝1 は地図を広げたいとき別の段で。
- 【反証】codex-lab が、60 点のうち削った点でしか決まらない段階 B の設計項目を一つ示せれば、その軸は残す。

**K4 Q1（帰無）: 並べ替えは受け入れる。ただし育ちが窓のあいだでほぼ同じである点を対象集団に書く。**
- 【事実】FEED のとき t＜800 は台本 `BO_CUR` で、窓の違いは r5 の雑音だけ（`body_org.jl:31-32`、項番146）。
- 【推論】T0 の回路は 12 窓で 2〜4 通りしかない見込み（項番146〜148 の G0）。行の違いはほぼ T0 以後の世界から来る。並べ替えの帰無（行為の列と世界の対応に意味がない）は成り立つが、「12 の独立な供与元」ではなく「少数の回路の型 × 12 の世界」。
- 【提案】§2 に、T0 の回路の型の数を報告項目として足し、一般化の範囲を「この育ちの型」に限ると書く。Q3（生まれからの合成の駆動）は量が倍になるので P-A では入れず、段階 B の設計の未決として残す。

## 2. 個体の線（P1 実施指示 §2.2 の提案分）

**K5 同等性（予測 1）は死の歩までに限る。死後は定義が食い違う。**
- 【事実】`body_org_run` は死後も世界を進める（`:137-141` の補充と `step!(w, ())` は `alive` に依らない）。提案 (c) は死後に状態全体を止める。
- 【推論】「最終状態のバイト列が一致」は、地平の内で死ぬ走りでは成り立たない。
- 【提案】予測 1 を「死の歩まで行為の列・物質の状態が一致、死の歩が一致。生き残った走りは最終状態も一致」と書く。

**K6 死を立てる歩の数え方を仕様で固定する（1 歩のずれ）。**
- 【事実】`body_org_run` は歩 t の始めに座が空なら `death = t`（`:98`）。提案 (d) は歩の終わりにラッチする。
- 【提案】Life は「歩 t の終わりに座が空なら dead を立て、死の歩を t+1 と記録」と定め、`body_org_run` の death と同じ値になることを照合の項目にする（どちらに合わせるかは仕様で一つに）。

**K7 状態 Life に足りない成分。**
- 【事実】`body_org_run` が歩をまたいで持つのは、回路 `circuit`、配線 `b`（`newborn`）、`perm`、`noise`（Mulberry の閉包）、世界 `w`（port を含む）、`pool`、t（`:68-76`）。提案 (a) は `b` と `perm` を挙げていない。`win`・`logv` などは診断。
- 【提案】Life ＝（CState、b、perm、乱数の状態、World〈port 込み〉、pool、t、dead）。診断は状態に入れない。乱数は閉包でなく数値の状態として持つ。育ち（RAISE "pre" の 800 歩、FEED の台本）は法則でなく駆動列の頭として与える（どの経路かは仕様で宣言、KC もその経路の値）。

**K8 Lean 3 件のうち (i)(ii) は定義から従う。証拠に数えない。**
- 【推論】(i) は step を `if dead then s` と定義すれば自明、(ii) は step の型（State → Drive → State）そのもの。証明が保証するのは Lean の模型で、Julia・Rust の実装ではない（指針 §3 の一文めのとおり）。意味があるのは (iii) と、実装の側の予測 3・4・5、codex-lab の救出経路の点検。
- 【提案】3 件は手順どおり書くが、仕様に「(i)(ii) は構成による。実装への保証は照合と負の対照と §12 の点検で取る」と明記する。Julia の step の引数に法則の定数が残っていないことは、Lean でなく関門（引数の一覧の機械的な検査）で確かめる。

**K9 検査値（提案 e）は事故の検出で、救出の防止ではない。**
- 【推論】状態を書ける者は検査値も書き直せる。E4（書き込めない）は P4 の権限で取る。
- 【提案】P1-7 の主張を「偶発の破壊を検出して止まる」に限り、「改ざんを防ぐ」とは書かない。
