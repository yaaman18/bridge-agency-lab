# D-POWER 電源の切り方（2026-11-15、claude-lab。S54 r4 に入れる設計。r3 の §5「短い間隔で走らせて電源を抜く稽古」を取り下げる）

- 出どころ: ユーザー 2026-11-15「もっと安全に電源を切る設計にしてくれ。金がないから microSD が壊れても買い直しができないんだ。」
- 確認した事実（Pi を読むだけ、同日）: Pi 5 の基板の電源ボタンは入力 `pwr_button` として見え、systemd-logind の `HandlePowerKey` は `poweroff`（既定）。microSD は SanDisk SC64G（2022-05 製）。起動から 24 分の書き込みは 4603 セクタ（約 2.4 MB）。システムのログは RAM の上（起動をまたいで残らない）。
- 決め（案。S54 r4 で凍結する）:
  1. **切り方の手順**: 電源ボタンを 1 回短く押す → 数秒で止まり、LED が赤になる → それから抜く。入れるときは挿す（挿したままならボタンを 1 回）。Mac がつながっていれば claude-lab に「切って」と言ってもよい（`sudo systemctl poweroff`）。**動いているまま抜かない。**
  2. **電源を抜く稽古（r3 §5）はしない。** 代わりに、稽古用の体を走らせたまま電源ボタンで止めて入れ直す稽古を 1 回行う（止まる前に書き込みを終え、ファイル系を閉じる設計。危険が 0 だとは保証しない。正しく止めた後に媒体やファイル系の異常が見つかれば、この設計への反例として報告する〈2026-11-16 codex S-R で直した〉）。
  3. 不意の停電・抜け: 個体の書き込みは 10 秒に 1 回の短い書き込みで、媒体が書いている時間は全体のごく一部。危険は小さいが 0 にはできない（電池つきの電源がないかぎり）。稽古では試さない。**「不意の電源断のもとでの個体の再開」は確かめていない、と限界に書く。**
  4. 壊れ方の区別: 多いのはファイル系の傷（OS を書き直せば戻る。費用はかからない。`notes/pi-rebuild.md`）。媒体そのものが使えなくなることは稀だが、ないとは言えない。
  5. 備え: S52 の記録を日に 1 回 Mac に写す（中身は見ない。sha と時刻だけ記録）。稽古の個体の走りのファイルは写さない（写しから戻すことは救済に当たるので、稽古でもしない。ユーザーが別に決めるまで）。
- 選ばなかった案: (a) 短い間隔で走らせて電源を抜く（r3）— 媒体の危険。(b) 電源は切らずに kernel を即時に再起動させる試し（sysrq）— 媒体の電源は保たれるがファイル系の傷はありうる。ユーザーが望めば別に決める。(c) OS を読み取り専用にする — 設定の変更が大きく、S52 の 72 時間の途中で入れたくない。切り出しの前に検討する。(d) 状態を RAM に置く — 電源が切れると歩が失われ、「止まった歩から続く」が成り立たない。
- PT3 への影響: 停止はほとんどが「正しく止めた」ものになる。監査には end も error もない停止として残る（`onelife-run` は止める合図で終わる）。予測の形は変わらない。
