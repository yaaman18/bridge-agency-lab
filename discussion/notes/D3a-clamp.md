## 0. 確認した事実（コード）

- C-F1 一歩の流れ（`variant_horizon.jl:126–145`）: 回路が受け取る収量は y＝min(5, ⌊pool/U⌋)（`:126`）の一つだけで、`LC.step!(c, b, [y1, y2, 0])`（`:129`）に渡る。
  身体が実際に取り込むのは take＝min(pool_k, d_k·U)（`:140`）で、d は回路が返す。
- C-F2 回路の中で y は**二つの経路**に使われる。
  - 感覚: 受容器の特徴 `feature(...)(ys, now, noise)`、ys は y から（`circuit.jl:100`・`:117`）。
  - 答え: 行為した区画の申し出 offer_k＝y_k（`:151`）→ allocate（`:86–91`、正の申し出にだけ配る）→ d → answered＝d_k＞0、gate（`:152–154`）。
    gate は確かめ（q の増え）を決め、bin3 の統計 cOn・cOff は dm＞0 を 1/0 で記録する（`:165`）。答えのない駆動は weaken・h の増え（`:199–201`）。
- C-F3 よって「環境の情報」は、受容器（感覚）と答え（gate・d）の**両方**から回路に入る。どちらも同じ y から作られる。D3 の ε・α・hSMC は受容器だけを扱い、答えの経路は数えていない。
- C-F4 S9 の 22.5%（結合した受容器を全部黙らせても移った）は、答えの経路だけで説明できる候補（推論）。S9 の α の照合で差が出ないのは、1 歩の取り込み（d·U ≤ 5U）が pool（上限 50U 付近）の ⌊pool/U⌋ を 5 未満に下げないため（推論、y の上限 5 で頭打ち）。

## 1. 提案: 三つの経路を分ける変種 CLAMP

アダプタに、一歩ごとに三つの値を分けて与える変種を足す（既定は今と同じ、三つとも同じ y）。
- y_sense（受容器が読む収量）、y_answer（申し出・配分・答えに使う収量）、pool（身体が実際に取り込むたまり）。
- 実装の案: `LC.step!` に省略可能な引数 `y_offer`（既定 nothing＝y と同じ）を足し、`:151` の offer をそれで作る。既定のときはビット単位で今と同じ（`sh core/check/run.sh` で確かめる）。
  アダプタの側で、y_sense と y_answer をそれぞれ「本物」「固定」「軛（よこ）」から選ぶ。
  - 本物＝その分岐の pool から作る y。固定＝分岐点 t の値に留める。軛＝無介入の分岐 N の y の列をそのまま再生する（同じ知覚の履歴を与える対照）。
- 取り込みの扱い: take は常に本物の pool で制限する（min(pool_k, d_k·U)）。y_answer を固定すると、回路が「答えがある」と思っても実際の取り込みは pool に依る。これは身体（価値）と回路の信号を分けることになる。

## 2. 三つの問いへの使い方

- Q-A（22.5% の正体）: S9 の Z（区画の交換）で、(i) y_sense を N に軛し y_answer は本物、(ii) y_answer を N に軛し y_sense は本物、(iii) 両方 N に軛。
  移りが (i) で残り (ii) で消えれば答えの経路、逆なら感覚の経路、(iii) で消えなければ回路の外の経路（身体の物質が回路に効く道はないはずなので、記録の誤りを疑う）。
- Q-B（α の照合）: 受容器の差が出ないのは y の頭打ちによる、が推論なら、照合を「m の行為が自分の区画の pool をどれだけ減らすか」（たまりの水準での α）と、
  「pool を閾値の手前に置いた状態での受容器の差」の二段に分ける。CLAMP は要らないかもしれない（下の論点 Q3）。
- Q-C（R3-d 価値への鈍さ）: y_sense を固定（感覚を揃える）、y_answer と pool は本物のまま区画の価値を変える（たまりの交換）。価値の変化は答えの経路でだけ回路に届く。
  sg で駆動される型と q で駆動される型が、答えだけで同じ速さで移るかを比べる（両方とも移らなければ推論しない、D4 R3-d）。

## 3. 論点

- Q1: 答えの経路を、D3 の読み（ε・α・σ は受容器だけ）の中でどう位置づけるか。DC の外の「環境から回路への第二の経路」として名前を与えるか（例 ε_ans）、それとも読みは変えず測定の側だけで扱うか。
- Q2: y_answer を固定・軛にすると、回路は「答え」を受けても身体は取り込まない（またはその逆）ことが起きる。これは世界の規則を壊す介入なので、結論を「この介入のもとで」に限ればよいか。
- Q3: α の照合（Q-B）は CLAMP なしで、pool の水準と閾値の手前の状態で直すべきか。
- Q4: `core/circuit.jl` に省略可能な引数を足すことの扱い（正本の変更。既定は不変。Rust には入れない）。それともアダプタの側だけで（y を二度渡す別の呼び方で）実現できるか。
- Q5: 軛（N の y の列の再生）と固定（t の値に留める）のどちらを主の対照にするか。

## 4. r2（往復1 の 1〜10 を反映）

- 名前（1）: D3 の定義（ε・α・σ は受容器だけ）は変えない。答えの経路は当面、測定の上の「答えの経路」と呼ぶ。ε_ans を読みに入れるのは別に定義してから。
- 身体から回路への道（2）: 確かめた。(i) 容量の規則 `enforce_capacity!`（`variant_horizon.jl:130`）は PER が nothing なら働かず、SF 版の BODY（`org` は PER を渡さない）では無効。
  (ii) **身体の死**は回路を止める（`:121–123`、死んだ系は活動を消し q が減衰）。これは身体から回路への道なので、分岐の窓（t＋15）の中で死んだ分岐は比較から外し、件数を記録する。
  (iii) 維持費 KC・行為の費用は身体だけから払い、回路の状態に触れない。この三つ以外の道は、下の同一性の対照で確かめる。
- **同一性の対照（3・10、経路の網羅の試験）**: Z で y_sense と y_answer の両方を N に軛すると、回路が受け取る入力は N と同じになる。身体の死がなければ、回路の状態・行為の列は N と**ビット単位で同じ**になるはず。
  一つでも違えば、まだ知らない経路か同期の不足があるので、Q-A の帰属の前にそれを調べる。
- Q-A の判定（3・4）: 判定するのは「移りの消失」ではなく、同じ初期状態・絶対時刻・乱数・sil のもとでの **N と Z の行為の列の差**（各歩の行為した区画運動の違いの数）と、S9 の (b) の判定の両方。
  条件: (o) 軛なし（S9 の Z）、(i) y_sense だけ N に軛、(ii) y_answer だけ N に軛、(iii) 両方 N に軛（同一性の対照）、(iv) S9 の結合した受容器の黙らせ（元の条件を保持）。
  言うのは「この介入のもとでの経路への依存」まで。二つの経路の相互作用・代わりがありうるので、一つの条件から唯一の原因とは言わない。
- 取り込みの不一致（5）: d＝0 なら take＝0 なので、起きうるのは「回路に答えがあるのに取り込みがない」（y_answer を本物より大きく軛したとき、take＝min(pool, d·U)）だけ。逆向きは起きない。結論はこの介入のもとでの依存に限る。
- Q-B（6）: CLAMP と分ける。照合を二段にする: (1) m の行為による自分の区画の pool の差（たまりの水準）、(2) 受容器の差。頭打ちの説は「比べる二つの分岐で y が同じ飽和域（y＝5）に留まる」という予測で検証する（y の列を記録）。
  閾値の近くでの照合は別の条件として先に固定し、元の α の定義は置き換えない。
- Q-C（7・8）: y_sense を固定して揃うのは外の収量の入力だけで、受容器の全体ではない（時刻・雑音・保留 pend。BODY では pend は空、時刻と乱数は分岐で同じ）。
  価値の変化が答えの経路で届くのは、交換で d＞0・gate が変わる場合だけ（例 生存の予定表 (5,0) の交換では、前の高い区画の y_answer が 0 になる）。交換の後に答えの信号が変わったかを記録し、
  変わらなければ「入力の差が足りない」で判定しない。両方の型とも移らなければ判定を保留する（D4 R3-d）。
- 実装の順（9）: `LC.step!` に省略可能な `y_offer` を足す案。正本の変更なので Lean を先に: 抽象の一歩で、申し出を y_offer から作る規則と「y_offer＝y なら元の一歩と同じ」の statement を書いて証明し、
  そのあと Julia。既定（nothing）と明示の y_offer＝y の両方で、状態と出力が元と一致することを `sh core/check/run.sh` と追加の照合で確かめる。Rust には入れない（アプリは v3.7 固定）。
- 軛と固定（10）: 主の対照は N の列の軛（同じ区画番号・絶対時刻で対応づける）。固定（t の値に留める）は補助。

## 5. 締め（案）
- 合意したこと: 環境の情報は感覚の経路と答えの経路の二つから回路に入る（コードの事実）。それを分けて固定する変種 CLAMP の設計（§4）、同一性の対照を経路の網羅の試験にすること、Q-A・Q-B・Q-C の判定のしかたと限定。
- まだしないこと: 実装と測定（S12 として §4′ の手順: Lean の statement → formal/check → 証明 → Julia → 照合 → 予測の凍結 → 走らせる）。答えの経路を DC・D3 の読みに入れること（別の議論）。
- 往復3 の限定（codex 3・4・6・7）: 共通の生存の対象で選んだ結果を S9 全体へ広げない。系列 B は S9 の 22.5% をそのまま再推定するものではなく、共通の生存の対象での経路への依存の検査。
  証明の完了後にも `sh formal/check.sh` を通して記録する。同一性の対照の一致が示すのは検査した条件・窓の範囲で、未知の経路が一般にないことの証明ではない。
- 元に戻す方法: 設計の前提（経路の事実 C-F1〜C-F3）がコードの変更や照合で崩れたら、この設計に依る判定を未判定に戻し、設計をやり直す。
