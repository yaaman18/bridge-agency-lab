# TRACE-1 の形成区間を接触時刻で切る案（案 X、2026-11-25 D 段、未承認）

- 由来: ユーザー「なんか２、３もエレガントじゃないやり方な気がするが、ベストプラクティスをcodexと議論してみて」。codex-lab 12:49Z・12:50Z・12:51Z（high）と 3 手。
- 出発点: TRACE-1（r5）は「時計と独立に試験の場が指定する痕跡形成区間」で進むことを求め、区間の長さ・判定点・切替の選び方は場が決める（requirements 159 行〜）。出典はラボの要件で、bridge-protocol の登録判定ではない。
- 案 X（codex P1〜P7 で合意）:
  - 起点 τ = min{t ≥ T | 実際の入力に対し、個体が受ける結果の条件分布が新旧の写像で異なる}。結果を引く前に場が決める。Y = 0・1 のどちらでも数える。時計の値にも重みの更新にも依らない。
  - 形成区間 = [τ, τ + L − 1]。K と期限は先に凍結する。期限内に形成区間を終えられない切替は、未検出として K に残す。
  - 未検出の内訳を併記する: 期限内に接触なし／接触したが L 歩不足／L 歩あっても未検出（最後のものが、接触待ちでは説明できない取り逃がし）。
  - 通常区間の対照: 擬似の切替時刻を先に置き、写像を替えずに、同じ新旧の写像対で分布が異なる入力の初出から L 歩とる。探しの期限と L は切替の側にそろえる。
  - 時計は自分の量のまま（C4 を凍結したまま）。主判定は r5 のまま。要件の文は変えない（場の決めごと、ラボ側、3 者合意と決定ログ）。
  - 遅れは同じ警報時刻 A で、A − T = (τ − T) + (A − τ) と分ける。T ≤ A < τ の警報は接触前として、応答に数えない。
- 確かめ方: 既見 48 生では、場の定義を替えた再集計として記述するだけにする。τ・対照・期限の扱い・C4・r5 を凍結し、未使用の生に T 起点と τ 起点の両方を当てて判定する。
- 読みの限界（codex P6）: T 起点で不成立、τ 起点で成立なら「その生では、起点の取り方で判定が反転した」まで。S80 の原因を確定したとは言わない。
- 手法の名前: 接触時刻にそろえた評価（event-time alignment）。
- 未確認の点（claude-lab）: 写像の切替が多くの入力の結果分布を変えるなら、τ ≈ T となって案 X はほとんど何も変えない。C4 の不足は、接触の遅れではなく「Y = 0 の例が少ないこと」のままになりうる。最初に、既見の生で τ − T の分布を場の側だけで（時計を見ずに）測るのがよい。

## 追記（2026-11-25、ユーザー「あなたの懸念の箇所の要件は一体どんな計算を使ってるんだ？」で、コードを読んで確かめた）
- 場の計算（`experiments/s72_open/s72.jl` 24〜47 行、`rbit`・`encode_map!`）: 写像 π は、学習器に見せる 8 個の受容器のうち 6 個（R1IDX = 1, 2, 3, 4, 7, 8）の並べ替えと反転。世界と Y（`st.Y`、行為した効果器の y > 0）は写像に依らない。写像は、学習器の入力の符号化だけを変える。
- 切替のたびに `draw_rho` は、恒等でない並べ替えと、6 個すべての反転（`trues(6)`）を前の写像に合成する。このため、T + 1 の最初の例から、すべての入力の符号化が旧写像のときと変わる。
- 帰結: 案 X の τ（新旧の写像で、実際の入力に対する結果の条件分布が初めて異なる歩）は、どの切替でも T + 1 になる。この場では、案 X は判定を何も変えない。
- 読み直し: 足りないのは接触ではなく、結果の情報量。Y = 1 がほとんどで（S81 の n0 は 1,000 例あたり中央値 5〜9）、予測が外れて証拠が立つのは主に Y = 0 の例。案 X は、この場では取り下げる。
