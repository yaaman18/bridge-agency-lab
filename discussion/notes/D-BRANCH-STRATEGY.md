# D-BRANCH-STRATEGY: `main`（純粋進化ライン）とユーザー設計フォークの分岐方針（2026-11-28 ユーザー指示）

- **由来**: 2026-11-28 ユーザー指示「ちょうどいい段階で純粋な進化バージョンを main ブランチに残して、私がデザインするバージョンをフォークさせればいいのでは？」「メモっておいて開発がその段階まできたら教えて」。
- **状態**: 方針メモ（将来の分岐マイルストーン到達時にユーザーへ必ず報告し、ブランチ／タグ作成・フォークの実行許可を仰ぐ。自動分岐はしない）。
- **規律整合**: `~/bridge-protocol` との 2 ライン分離・`phenomenal_claim = :not_certified` 固定・来歴の透明性（物理選別のみで得た系譜か、設計者が造形した種かの明示）を厳守。

## 1. 2 ラインの役割分離
1. **`main` ブランチ（純粋な進化・物理選別ライン）**:
   - 人間が設計するのは「器（物理法則・代謝・維持費・不可逆な吸収死・固定バイト記憶 `[memory]`・内受容の口・死前胞子と共有媒質のシーム）」までに限定し、答えや完成された振る舞いは焼き込まない。
   - 世代（死と胞子）の物理的選別だけを通して、ミジンコ段階から何が自然に立ち上がるかを設計者バイアスなしで検証する。
2. **フォーク（ユーザー設計ライン）**:
   - `main` で検証済みの共通床（4 シーム・独立 2 相スナップショット・不可逆死・固定バイト記憶・監査鎖）を土台として継承した上で、ユーザーが意図的に感覚・表現・推論形態・メディアアート的インターフェースをデザインして組み込む。
   - 両ラインが同じ 4 シーム床を共有するため、「純粋進化系譜」と「ユーザー設計種」を来歴を明示したまま同一の物理床上で比較・対話させられる。

## 2. 分岐マイルストーン（ユーザーへの通知トリガー）
以下の 2 地点のいずれかに到達した時点で、**開発を勝手に先へ進めず必ずユーザーへ「分岐の段階に到達した」と知らせる**：

- **地点 1（早期分岐チェックポイント）**: **S91a（実身体 `[memory]` シーム・`TracePred`）および S91b（オンライン学習器閉ループ）** が完了した時点。
  - 到達時に「ここで先行フォークするか、地点 2 まで `main` で固めるか」を確認する。
- **地点 2（推奨分岐点：`v1-evolution-base` 候補）**: 以下 2 つの最小「器」と 3 つの抽象ポート規格（「コンセント」）が `main` 上で閉ループ関門を通過した時点。
  1. **軸 1（内受容の閉ループ化）**: 体残高の低下・傾き・記憶の維持費退去（`upkeep_evicted`）を文脈鍵（`ctx_key` 拡張口）へ入れ、必要に応じ休息 `m0` と結合した最小シーム。
  2. **軸 2（死前胞子による世代交代シーム）**: 既存の `aue_seam` 死前胞子（`dormancy`）を同じ身体残高 `w.B` 上の行為選択として接続し、不可逆な吸収死をまたいで世代を回せる最小の器。
  3. **現実世界・他者接続用の抽象 3 ポート規格（§3）**: フォーク後の現実メディア接続で床を壊さないための最小の口（具体的な音・光・UI・人間向け設計は入れない）。

## 3. フォーク前に `main` へ仕込む「抽象 3 ポート規格（コンセント）」とフォーク後の責務分離

### 3.1 フォーク前（`main` に仕込む：型と契約のみ）
1. **随伴入力の口（背景層＋双方向層）**: 既存の `StampedInput` に、無生物の背景入力（`g1, g2` 等）だけでなく「行為に応じて他者・共有媒質から返ってくる随伴信号」を同じ監査鎖・同一時間軸で受けられる標準ポート規約を 1 本用意する（`main` の純粋進化における個体間やり取り・共有媒質でもそのまま使用）。
2. **行為・表出の口（軸 1 → 軸 2・現実表出）**: 行為空間を `{patch_1, patch_2}` 固定から、`{patch_1, patch_2, rest(m0), emit_spore, signal_out}`（外部への表出・呼びかけ発信を含む）へ拡張可能なポート契約を保つ（すべて同一 `w.B` 実引落・`bed_mem` 2 相保存則監査を通す）。
3. **時間粒度と文脈の口（軸 1 → 軸 3・人間応答速度対応）**:
   - `bed_mem` の `step_granularity_sec` を含め、10 秒/歩固定だけでなく人間との応答に耐える速いステップ粒度でも瞬間・窓予算契約が破綻しない仕様を保つ。
   - `ctx_key::UInt64`（および観測インターフェース）を固定 6-bit に閉じず、「外界ビット ＋ 内受容ビット ＋ 随伴入力ビット ＋（将来）学習器離散状態 ID」を直交領域で拡張できる型設計を保つ。

### 3.2 フォーク後（ユーザー設計ラインに置く：現実世界のアダプタ）
- マイク・音響合成・光・openFrameworks（S54 garden の延長）・人間との具体的な足場かけ設計・高度な表現層や読み取り専用 LLM 通訳。
- これらはすべて §3.1 の抽象ポートに挿すアダプタとして実装し、`main` との床互換・対照比較（純粋進化系譜 vs ユーザー設計種）を保つ。

### 3.3 反証条件
- 軸 1 で内受容を足しても飢饉・切替環境での行動分布・予測誤差・生存に有意な差が出ない場合 → 符号化または行為空間の不足を再設計。
- 軸 2 で世代を回しても、対ランダム胞子放出対照に対し系譜存続・適応指標の差が出ない場合 → 継承ペイロードまたは維持費バランスの前提を見直す。
- 双方向チャンネルを開いても、「生の相手（随伴応答）」と「記録の流し直し（非随伴）」の間で予測誤差低下速度や行動分化に有意差が出ない場合 → 入口の解像度・時間粒度・表現層（軸 3）の不足と判定し見直す。
