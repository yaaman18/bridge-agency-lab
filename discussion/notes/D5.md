## 1. 主題（提案 R4）

**R4-a（二つの L2 を分ける）**: ラボで「L2 が真」と書くときは、道具の L2（V-F2）か Lean の Agent（V-F1）かを必ず明記する。道具の L2 の真から Lean の Agent を推論しない（DC の証明書がない）。
Lean の Agent の証拠と言うには、同じ物・同じ走りで、D2 の T（DC の証明書つき、事象ごと）と、道具の L2 の各成分を、同じ契約で並べる。

**R4-b（構造の価値の読み）**: bp の価値は「環境の結合が νΦ に寄与する度合い」で、収量そのものではない。ラボは今、選択の予定表の収量の大小で「価値の違い」を作っている（choice_params）。
この読みの差を明記し、`viabilityContribution` をラボの κ・π・ρ（F3）から計算する案（受容器 e が駆動する運動の行為で確かめられた κ の辺の数）を S 段の候補にする。

**R4-c（ValueNeeded と意味情報）**: ValueNeeded（T を黙らせると生き残れない予定表がある）は、P078 の「相関をかき混ぜると存在を保てない」と同じ形の介入による必要性の判定と読める（推論、型の対応だけ）。
S12 の軛（回路の入力を無介入の分岐の列に置き換える）は「系と環境の相関をかき混ぜる」介入の一つの実装になりうる。ここから意味情報の量（生存の差）を測ることは S 段の候補にとどめ、今は定義を変えない。

**R4-d（言わないこと）**: L2・Agent の真から、価値が系に「とって」意味を持つこと（mattering）、快・不快、目的、意識を言わない（bp `Agency.lean:16–19` の分離定理と同じ立場）。
最大化（empowerment・報酬）を価値の読みに使わない（X5、D3 LE6）。

## 4. r2（往復1 の 1〜11）

- R4-a（1・8・9）: 並べるだけでは Lean の Agent の証拠にならない。`ValueDifferentiated` は**構造の価値**の差を要求するので、収量の差で作った二つの予定表について、構造の価値（R4-b の計算）が実際に違うことを別に示す。
  同じ物・同じ走り・同じ契約で、DC（D2 の T）・構造の価値・選択・ValueNeeded の表を記録することは**必要条件**で、同じ対象への写像が Lean の各述語（`Agent` の各欄）を満たすと照合して初めて Agent の証拠になる（往復2-2。S7 と既報の L2 の集計を合わせただけでは実例にしない）。
  時刻・窓・摂動の集合・介入の対象の対応は測る前に固定する。成り立った T⁺ の区間だけを後で選ぶなら、主張はその区間に限り、走り全体の Agent の証拠にはしない。
- R4-b（2・10）: ラボの構成素 C は結びつき（辺）なので、`contribution(e)`＝「窓の中で、受容器 e が駆動した行為で確かめられた辺の**集合**」（`core/dc.jl` の via[e, k]）、
  `viabilityContribution(e)`＝|contribution(e) ∩ νΦ_t|（νΦ_t は窓の Φ_t の最大不動点。有限の集合なので全体から Φ を繰り返して求める）。数えるのは異なる構成素の数で、駆動の回数ではない。
  沈殿で生きる腕でこれが 0 になっても「価値がない」とは言わない。この写像が沈殿による寄与を落としている可能性を記録する（DC が沈殿を数えないのと同じ、X1）。
- R4-c（3・4）: 対応は「介入による必要性」という抽象の形まで。ValueNeeded は二つの側（T ありだけで生きる摂動がある、かつ T なしだけで生きる摂動がない）を要求し、P078 の必要性の片側とは同じでない。
  T の黙らせは相関以外の能力も変えうる。S12 の軛は、無介入の分岐の列が同じ環境を共有するので相関の一部が残る。軛を「相関をかき混ぜる介入」と呼ぶには、何が崩れ何が保存されるかを先に定める（S 段の候補）。
  生存の差は介入の効果で、そのまま意味情報の量とは呼ばない。
- R4-d（5）: 「価値の読みに最大化を仮定しない」と「最大化的なふるまいがないと言う」を分ける。後者は言わない。
- LV1（6）: 分離定理は bp の記述を引くだけで、ラボは証明の中身を点検していない、と明記する。LV2（7）: T は二つの予定表と窓に依って同定される集合で、系に固定した単位の集合とは読まない。
- Q3・Q4（11）: 限定した比較はラボの読み。定義の同値・変更を言う段階で bp-proposals。P012 は未取得で、その条件（個体性・規範性・非対称性・時空間性）との整合は未評価と明記する。

## 6. 締め（案、decisions-log #7）

- 合意した読み（§4 の修正版）: R4-a（道具の L2 と Lean の Agent を分け、同じ走り・同じ契約の DC・構造の価値の差・選択・ValueNeeded の併記は必要条件で、Lean の各述語への写像の照合で初めて Agent の証拠。窓と摂動は先に固定）、
  R4-b（構造の価値のラボでの計算: 受容器 e が駆動した行為で確かめられた辺の集合と νΦ の交わりの大きさ。0 を価値なしと読まない）、
  R4-c（ValueNeeded と意味情報は介入による必要性の抽象の形が似ているだけ。軛を相関のかき混ぜと呼ぶ前に崩れるものを定める）、R4-d、LV1〜LV3。
- 未実施: 同じ走りでの DC・構造の価値・選択・ValueNeeded の併記の測定（S 段）。構造の価値の計算の実装（Lean の `viabilityContribution` との照合つき）。P012 との整合。
- 選ばなかった案: 道具の L2 の真から Agent を推論する、収量の差を構造の価値の差とみなす、κ の辺の駆動回数で価値を数える、軛をそのまま相関のかき混ぜとする、生存の差を意味情報の量と呼ぶ。
- 元に戻す方法: 写像・測定の前提または形式との対応が崩れたら、それに依る認定を未判定に戻す。有効な測定で固定済みの基準を満たさなければ、その対象・区間・摂動の集合について不成立として記録する（往復2-4）。追加の実験や P012 の取得は読みの合意の条件にしない（往復2-5）。
