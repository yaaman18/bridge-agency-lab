## 1. 確認した事実と『11月23日のメモ.md』の不足要素（優先順位確定）

### 1.1 最優先セット（閉ループ物理種 `AUE-C` 以降の必須関門；`AUE-A` 配備条件には含めない）
- **A4（ライブ非ビット一致時の反証関門）＋ A2（随伴性が閉じる物理エフェクタ）を一組として扱う**：
  - ライブ音響・光等の物理帰還ループでは事前計算とのビット一致を手放すため（メモ `:159`）、切り出し前の別走行で「同一費用で物理エフェクタ（例：LED・スピーカー）を駆動しつつ、感覚入力だけを過去記録列へ置換した軛対照」を置き、外乱後の維持回復に**走行前に凍結した回復指標・観測窓・判定規則**で差が出なければ、当該条件での物理帰還の寄与を棄却する（判別精度不足の走行は保留）。

### 1.2 メモから欠落していた 4 つの構造要件
1. **全種共通の BP 述語（AGENCY-001）不変性と「種（Type）対 変種（Variant）」の区別基準**：
   - 種ごとに合格基準を変えるとゴールの付け替えになるため、BP 述語は全種共通とする（ユーザー承認事項：U-SP1b）。
   - **種（Type）の定義**：`species_spec.toml` が許す**「個体境界・基質・ポート集合・許可された認知器官型の集合」**で種を定義する。許可集合の**内側**での器官交代・分化は同一個体・同一種とし、集合の外へ出る変更は新しい種とする（反証条件：許可集合外への交代を種変更記録なしに通せる経路があれば設計誤り）。**変種（Variant）**は同一種仕様内の定数・重み差とする。
2. **個体境界・出生・死・胞子/休眠の系譜規約**：
   - 親が吸収死した後に胞子／休眠庫から発芽する系は「同一個体」と数えると吸収死と矛盾するため、**「系譜上の子（別個体）」**として扱う。
   - **内発性条件（`promise-cutout.md` 整合）**：胞子を系譜上の子として認めるのは、外部監査鎖上で **胞子の生成時刻が親の吸収死より前（内発生成）** だと証明できるときに限る（死後に運用者が生成すれば禁止された救済）。
3. **終了記録の 3 区分分離（ハード死を代謝死の述語から外す）**：
   - 吸収状態としての死の会計を汚さないよう、終了記録を次の 3 区分に厳密分離する（Julia 正本で定義し Rust とビット照合）：
     - `metabolic_or_org_death`: 最終保存状態で確認された代謝・組織の死（$\kappa=\emptyset$／物質空）。
     - `non_metabolic_termination_verified`: 停電・SD 破損・基盤故障など、外部 OS 証跡（`boot_id`/`dmesg`/`tune2fs` 等）で裏づけられた非代謝終了。
     - `unexplained_truncation`: 外部証跡なく記録が途絶した原因未確定終了（代謝死にもハード死にも混ぜない）。
4. **動的器官交代時の意味論監査（BP11 / H8 拡充）**：
   - 同じポート値でも器官交代後に環境への効果が変われば、`mapping_spec_hash` 一致だけでは不十分。`audit/dc_mapping_audit.jl` 型の動的介入 `α` 照合を併用し、介入結果が登録済み `α` と食い違った版では意味対応の判定を保留する。

## 2. 多型 AUE 基盤の 4 破綻反例と構造対策

1. **反例①（1 TB 休眠庫の無料記憶化）**：休眠モジュール・種子バンクに維持費を課さないと無料の外部記憶になり物質会計が破綻する → 休眠庫も物質会計または低率維持費・有限スロット枠の対象とする。
2. **反例②（連続力学系の `B_max` 隠蔽）**：連続系（Type-C）で「1 歩」の粒度を細かくして 1 歩予算を見かけ上小さくできる → `species_spec.toml` で**歩の粒度定義・1 歩予算 `Budget`・壁時計時間あたりの総予算上限**の 3 つを同時凍結する。
3. **反例③（複数 AUE 共有媒体の境界・資源二重取得）**：他 AUE の出力が自分の入力になる共有媒体では、`b_shell` は個体ごとに切り他個体は「世界側」へ置く。監査鎖は **「個体ごとの鎖＋共有媒体の鎖」の二重構造** とし、同一の資源授受を指す共通 **`event_ref`** ID を持たせて二重取得を照合する。
4. **反例④（物理共鳴器の未刻印アナログ状態）**：未刻印のアナログ物理状態が次状態を分岐させる場合、1 歩決定契約の再生監査は反証される → 適用限界として明記し、A4 の摂動回復試験へ切り替える。

## 3. `PLAN-PI5-TRM-DEPLOY.md` へ組み込む最小の 4 継ぎ目（過剰設計の防止）

- **Phase 1〜2（S64 重み確定・Pi 5 単体照合＆`B_max` 校正）は一切変更しない**（第一号 `AUE-A` を遅らせない）。
- **Phase 3（`rust/onelife-trm`）に入れる多型対応の継ぎ目は次の 4 部品のみ**（まず `AUE-A` 1 実装だけで Phase 3〜5 を通し、Type-B〜D は同時実装しない）：
  1. **`species_spec.toml`**：種 ID・個体境界／出生／死／親子継承可能状態・許可器官型集合・ポート宣言・歩粒度＆予算上限を記述し、その SHA と `mapping_spec_hash` を監査鎖ヘッダへ刻印。
  2. **`Port` 契約**：申告済み読み書き＋入力刻印 `input` 行。
  3. **`Ledger` 契約**：物質・維持費会計＋3 区分終了コード（Julia 正本先行→Rust ビット照合）。
  4. **1 歩契約**：`step(state, stamped_in, budget) -> (state', declared_out, cost)`（`systemd` は床ではなく Pi 5 配備手段へ分離）。
- **検証範囲と反証条件（基準日 `2026-11-23`）**：
  - Julia で第 2 種（既存 S61c CPC 等）を床コード無変更で通して確認できるのは「仕様上の継ぎ目の妥当性」までとし、**Rust 床の汎用性は第 2 種が同じ Rust 床を通るまで未主張（保留）**とする。
  - *反証条件 (a)*：第 2 種を通すのに床コード改変が要れば継ぎ目設計の誤り。
  - *反証条件 (b)*：継ぎ目作業で `AUE-A` の Phase 1〜2 完了（基準日 `2026-11-23` 起算）が 1 週間以上遅れるなら過剰設計として削る。
