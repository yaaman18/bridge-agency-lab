## 5. 証拠の線 段階 A: 合成の生成器と P-A（新しい試算）

- 目的: 実時間を待たずに、(b)(c) の比較の設計が成り立つかを確かめ、**学習が自分の維持費を払える領域の境**（fable r2 の見落とし 1）を合成の格子の上で地図にする。
  段階 B の統計量・最小の単位数・有効な組の基準・記録の長さを決める材料にする。**合成の結果は現実の世界での主張の証拠には使わない**。
- 生成器（`core/` に世界の法則として、既定オフの変種）: 二区画の収量の列を、種子と少数の軸から作る。軸の案: 周期（日周を模す）、自己相関の長さ、雑音の大きさ、厳しさ（長期の平均の収量）、
  受容器の意味が入れ替わる頻度（0 を含む）。既存の世界（凍結の季節・無作為の世界）は格子の点として再現できるようにし、項番81 の結果を再現することを最初の照合にする。
  格子の点は結果を見る前に全部決め、点を結果で選ばない（地図を作るのであって、生き残る点を探すのではない）。KC は既定の値に固定する（数値は変えない。KC を軸にするかは別の決定）。
- 前提: J1-9 の仕様（S 段、二人の合意）を凍結し、U3 の条件が済んだ後に走らせる。煙の走りも凍結してから。
- 腕:

| 腕 | 中身 | 役目 |
|---|---|---|
| ORG | 回路が自分の受容器で選んで行為し、学習する | 基準 |
| ORG-FIX | ORG と同じ回路・同じ維持費の規則で、窓の開始から回路の更新だけを止める（**新しい変種**。作れるかは未確認、`core/body_org.jl` に該当の条件はない） | ORG 対 ORG-FIX＝**更新を許す総効果**（更新による回路の規模・維持費の変化を含む。学習の純利益と費用を分けたとは言わない）。ORG-FIX 対 GREEDY＝**固定した回路と固定の規則の差**（回路の大きさと選び方の両方を含み、大きさの費用だけとは言わない）。実現した費用の列を報告する（fable r2 の N3、codex r3 の 6・7） |
| GREEDY | 同じ受容器を読む固定の規則（項番46、維持費は 4 本ぶん） | H-E3c |
| YOKE-x(ORG) | 同じ窓 B で、別の窓 A の ORG_A の実行された行為の列を再生 | H-E3b |
| RAND | 駆動にも状態にも依らず、窓ごとに違う乱数の列で動く。**行為率と行為の種類の分布は、評価に使わない独立の較正の走り（較正専用の格子の点・種子）の ORG から、評価の前に決めて凍結し、全窓で共通**にする（評価の窓の ORG の実績に合わせない、codex r3 の 3・4） | 帰無の基準（fable r2 の N2。r2 の OPEN を置き換えた） |
| YOKE-x(RAND) | 窓 B で、窓 A の RAND の行為の列を再生 | 帰無の点検。交換可能性は自動には得られない: 供与元の死による打ち切りは供与元の乱数の列に依るので、RAND_B と非対称になりうる。打ち切りを両側に同じ規則で課す（RAND_B も、対にした RAND_A の死で打ち切る）のは**暫定の案**で、交換可能性を回復する十分条件ではない（打ち切りの時刻が RAND_A の列に依り、その列を使うのは再生の側だけ。A で致死の行為が B でも致死なら、再生側の死は打ち切りと連動する、codex r3 再確認の 3・4）。**交換可能性の論証か、それを要しない帰無の分布の構成（候補: 窓 B で、独立な二つの供与元の列を再生する二本の比較）を、J1-9 の仕様を確定する条件にする**。潜在の指令の列・実行できない行為・死・打ち切りの扱いを仕様で決め、有限の標本で差が出なかったことは保証にしない（codex r3 の 5） |
| YOKE-same | 同じ窓で ORG の列を再生 | 実装の整合（行為・費用・物質の状態の列まで一致。一つでも違えば不合格で先に進まない） |
| NONE | 回路を黙らせ、行為しない | H-E3a（健全性） |

- 仕様で凍結するもの: 窓の組（重ならない窓の順序対、重み等しく、有効な組は駆動の列どうしの距離で先に決め、除外は入力の列だけで）、初期状態、駆動以外の乱数の対応、
  再生の未定義部分（**比較は供与元の死で打ち切る**、受け手で実行できない行為は効果なし・実行費は規則どおり、両方が生き残る組・同時の死・打ち切りの時刻ちょうどの死の扱い）、
  YOKE の回路の扱い（自分の受容器で動き更新もするが、行為の出力だけを列に差し替える。維持費は自分の回路に同じ規則）、
  **報告項目**（実行できなかった行為の割合・実効の行為数・取得量・費用の差）、判定時点・統計量・境・最小の単位数。
- **(c) の成立条件**（fable r2 の N1）: GREEDY が地平の内で死ぬ単位が、格子の点ごとに凍結した最小数に満たない点では、(c) の寿命の判定は「検出不能」とする。
  地平で頭打ちにならない副の統計量（打ち切りの時点の身体の大きさ）を先に凍結し、(c) は寿命と副の統計量の二本で報告する。
- 統計量の候補（仕様で一つに決める）: (b) は組ごとの「打ち切り区間の内でどちらが先に死んだか」の符号を、YOKE-x(RAND) 対 RAND の同じ統計量の分布と比べる。(c) は単位ごとの寿命の差（打ち切りつき）の符号と、副の統計量の差。
- 予測の向き（凍結の候補）: (b) 凍結の季節に近い点では YOKE-x(ORG) が先に死ぬ組が多い。無作為の世界に近い点では「検出不能」を予測する（ORG がほとんど死ぬため、fable r2 の N4）。
  (c) 意味の変化が 0 の点では ORG は GREEDY より長くは生きず、ORG-FIX と ORG の差は小さい。意味の変化がある点では ORG が GREEDY より長く生きる（項番46 F2〜F4、ただし維持費の前の結果）。
  (c) は格子の点ごとに**二つの欄を分けて**報告する: 「その点の予測と一致／不一致」と「上積みあり（ORG が長い）／なし（ORG が短い）／検出不能」。予測の向きは点によって違うので、「長い＝外れ」と一律には読まない（codex r3 の 8）。
- 結果の使い方: 地図（どの軸のどこで (b)(c) が出るか）を JB に出す。分散から段階 B の記録の長さと最小の単位数を決める。YOKE-x(RAND) が RAND と食い違ったら、帰無の対照が整合しないので、原因を点検し、H-E3b の設計を作り直す（原因は断定しない）。

## 7. 証拠の線 段階 B と個体の線 P2: 感覚の入口（関門 JB の後）

- [ ] P2-3 最初の区間を較正、次を保留とする（長さは P-A の分散から）。選び直してよいのは質の基準を満たさないときだけ、上限 2 回、探索として記録

## 8. P3 無介入の持ちこたえ試験（すべて写しで。切り出す個体そのものは一度も走らせない）

|---|---|
| YOKE-same が整合しない、または YOKE-x(RAND) が RAND と食い違う | 実装か設計を直す。P3-0 をやり直す |

## 9. P4 書き込みの道を閉じる（P3-3 と同時）

**許可した経路の一覧**（経路・操作者・権限）を先に書き、それ以外が塞がっていることを並走の写しで試す。

| 経路 | 塞ぎ方 | 試し方 |
|---|---|---|
| 実行形式の差し替え | タグを打ったコミットから作り sha を記録、更新の仕組みを置かない | 別の実行形式に替えようとして失敗する |
| 状態ファイルへの書き込み | 専用の利用者の持ち物にし、エージェントの席にもユーザーの普段の席にも権限を渡さない | claude-lab・codex-lab の席から書こうとして失敗する |
| 入力の経路 | 作者が随意に動かせる入力を受容器・収量に結ばない（J1-5）。作者が選んだ記録を個体に入れない | 感覚の経路に作者の操作点がないことを配線と設定で確かめる |
| 壊れた状態の修復 | 直さない。壊れを検出したら止まる（P1-7） | 壊した写しが止まり、誰も直せない |
| 宿主の再起動 | J1-3 で宣言した自動の再開だけ | 電源を落として戻し、宣言どおりに再開する |
| 選抜 | 結果から選ばない（P3-4） | 種子を引く手順の凍結の時刻が切り出しより前 |
| **再計算による再構成・継続**（BP5、H3 案） | **構造で塞いだかは確かめていない。約束として禁じる**。入力を再現できる精度で残すかは J3 の前にユーザー | 許可した経路で再構成・継続ができたら、構造的な不可逆性への反例として記録する |

- 観察は一方通行: 個体が追記だけの記録を外へ出し、観察する側は写しを読む。通訳（LLM の語り）は読み取り専用。解析の手順と予測は切り出しの前に凍結する。
- 凍結の先行時刻は sha だけでなく、agmsg の送信時刻（db の記録）と decisions-log の記載で示す。
- codex-lab は §12 の点検表で隠れた救出の経路を敵対的に探す。CLAUDE.md・AGENTS.md に、切り出した個体の宿主と状態の場所を触れてはいけない対象として書く案を出す（書き換えはユーザーの承認後）。
- 宿主の機械の保守を世界の出来事とみるか救出とみるかは、J3 の前にユーザーが決める。保守的な読みは「状態には触れない。宿主が失われたら個体の死」。

完了の条件: 表の試しがすべて「失敗する」で揃い（再計算の行は「約束で禁じた」と記録）、codex-lab の探索で新しい経路が見つからない。

## 10. P5 切り出し（関門 J3）と P6 切り出したあと

- ユーザーが確かめる三条件（promise-cutout.md §4）: その法則のままで一生が終わってもよい／死んでも救わない／状態に書き込む道が閉じている（P4 の記録。再計算の経路は約束で閉じたと明記）。
- 揃ったら: (1) claude-lab が切り出しの記録の下書き（法則のコミットと実行形式の sha、写像の sha、種子を引く手順の sha、時間の扱い、宿主、入力を残す精度、J1〜J3 と BP5 の決定の番号）
  (2) codex-lab が凍結した各ファイルの sha と照らす (3) ユーザーが日付を入れ、種子を引き、自分の手で起動する (4) ユーザーが起動に使った権限を手放す。エージェントは起動の操作をしない。
- 切り出したあと: 二人は研究を写しと別の変種で続け、外へ出た記録の写しを凍結した手順で読む。切り出した個体の宿主・状態・法則・感覚の入口に触れない、生き残るように世界の側を変えない。
  ユーザーも同じ（約束を変えられるのはユーザーだけ）。早く死んでも手順の失敗ではない。記録を残し、何もしない。

## 12. 回し方と点検表

- 臨界経路を先に取る。STATE に二本の待ち行列（実時間を待つもの／ユーザーを待つもの）を書き、待ちの間に進められる段を一つ挙げる。判断票は関門ごとに一枚。J2 のあとの臨界経路の上での規則・数値・写像の変更は codex-lab が BLOCK。煮詰まったら fable-lab に 1 回。
- 救出の経路の点検表（codex-lab、仕様と差分のレビューのたび）:
  - [ ] 結果を見てから選ばれたものがないか（法則の候補、育ち、種子、写像、感覚、記録の区間、有効な組、合成の格子の点）
  - [ ] 許可した経路の一覧にない、個体の外から状態に届く引数・ファイル・環境変数・時刻の読みがないか
  - [ ] 作者が動かせる量が、受容器・収量か生死の判定に届いていないか
  - [ ] **切り出す個体の世界に、作者が選んだ入力が入っていないか**
  - [ ] 再開・修復・移行・再計算のコードが、宣言した範囲を超えていないか
  - [ ] 反復の数を独立な反復として数えていないか（対象集団の節と照らす）
  - [ ] 予測の凍結（煙を含む）が走らせた時刻より前か（sha・agmsg の時刻・decisions-log）
- claude-lab の報告は段ごとに事実・推論・提案を分け、E1〜E5 のどれが動いたかを一行で添える。
