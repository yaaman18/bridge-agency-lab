## 推論

- b_n は確かめの期間に大きく下がった（設計期間の SD で −1.9 個分）。固定の標準化のもとでは、区画 2 の応答率が 0.79 から 0.52 に下がり、電波だけの系列の区画 2 は 0.127 まで落ちた（P-S65-2 は C4_full だけが対象なので、これは判定に入らない）。
- RATE は凍結した値なので、このずれの分だけ大きく損をする。たとえば C4_radio_only の RATE は 1.33 nat。したがって (a)(b) が大きく出たことの多くは「凍結した RATE の較正が外れた」ためであり、時間構造を追えていることの直接の証拠ではない。
- これに対し (c) の D_shuf は、確かめの期間の中で行を入れ替えた対照との比較なので、周辺分布のずれは打ち消し合う。こちらは時間構造の寄与と読める。ただし保守下限は 0.042 で余裕は薄く、L=720 では 12 ブロックしかない。
- TAB4 が B1 を上回ったのは C4_full と C4_noradio だけで、zshuf と radio_only では下回った。設計期間で学習した表の利得は合成周期の側から来ている可能性がある。ただし原因は特定していない（仕様 §5 のとおり、損失差だけから断定しない）。

## 仕様にない実装上の取り決め（I-R で点検してほしい点）

- `Mulberry(650002)` は L ごとに新しく作り直す。B=5000 回の各回で nb 個の添字を `floor(r()·nb)+1` で引き、全系列・全統計で共有する。
- 点推定は全 N 行でとる。CI は nb·L 行（端数を切り捨てた範囲）でとる。
- TAB4 の数え上げは設計期間で凍結し、確かめの期間には足さない。確かめの期間の先頭 4 行の履歴は 0 で埋める（設計期間の末尾は引き継がない）。
- 反転を確かめる行は `k = floor(j·N/50) + 1`（j = 0..49）で、4 系列すべてについて確かめた。
- 丸めは `synth_world.jl` と同じ Julia の `round`（同点は偶数へ）。
- 1 回目の実行は入力のパスの誤りで、元の写しを開く前に止まった（何も読んでいない）。その後、引数の検査の 1 行を直し、最終版で out・out-rerun・final を走らせ直した。
- `confirm_72h.tsv` は元の電波の行そのもので、`.gitignore` には入っていない（`design_72h.tsv` と同じ扱い）。コミットするかどうかは決めていない。
