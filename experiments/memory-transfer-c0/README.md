既存の C0 の計画・系統の既定・実個体（S54 の試運転を含む）・アプリの db・既存の凍結・`~/bridge-protocol` は変えていない。
主張に使う種子の列（次は 886）は使わず、独立の区画 52xxx を使った。結果は主張の根拠に数えない。Codex のレビュー（I-R）はまだ受けていない。

## 手順（実際に行った順）

1. 予測・反証・対象・採点 `predictions.toml` → `shasum -a 256` を `../freeze-memory-transfer-c0.txt` に記録（7909a5b9…551b、20:38）。52xxx の世界はまだ一つも生成していなかった。
   凍結の前に走らせたのは、時間を測るための既存の種子 686 の 1 回だけ（中身は見ていない）。
2. Lean `formal/MemoryTransferC0.lean`: statement（`sorry`）→ `sh formal/check.sh` → 証明 → 再検査（`sorry` なし。公理は propext・Classical.choice・Quot.sound）。
   - `leak_mem`: 痕跡 m ← m + (y − m)/8 は [0, 1] にとどまる（B1 の p は切り詰めの前から確率）。
   - `lpScore_split`: 局所積の点は行為ごとの文脈の読み Σ_j (w_0j + σ_a w_1j) c_j に等しい（移した w と個体の文脈 c だけで点が決まる）。
3. Julia `c0.jl` → `out/`（関門・訓練・評価・採点、8 スレッド）。
4. 別プロセスの再実行 `out-rerun/`（1 スレッド）。`results.tsv` の SHA-256 が一致（738961f5…d7ad）、記録 48 ファイルも全部一致。`shasum -c` で凍結を照合して OK。
5. `sh core/check/run.sh` → `core-check.out`（exit 0）。追跡されているファイルは開始時から変わっていない（`git status`）。

## 解釈

- 確認した事実: この合成世界の族と UNI の行為の分布の上で、選ばれた行為の応えの予測は、訓練の世界から w（6 個）だけを新しい個体へ移すと、
  未見の 23 の世界のすべてで行為ごとの割合 RATE より損失が小さく、18 の世界で痕跡一つの B1 より小さかった。痕跡を読まない同じ学習の LP0 は RATE とほぼ同じ。
- 推論: LP の優位の中身は二つ。(1) 各行為が自分の痕跡を読む係数（約 4.4）が B1 の「p = m」をロジスティックで較正し直している。
  (2) 他の行為の痕跡への小さな負の係数（約 −0.14〜−0.28）。どちらが大きいかは分けて測っていない。B1 が RATE に勝つことから、応えのない歩は時間に固まっている
  （周期の谷の入り口で y が 0 になる）と読める。族の外（周期を変えた世界）でも向きは保たれたので、w は周期そのものを覚えたのではなく、痕跡と応えの対応を運んでいる。
- 空の合格の点検: 応えの割合が約 0.99 なので差の絶対値は小さい（点の差の中央値は 0.002〜0.004 nat）。応えなしは族の中で 789 例あり、比較の土台は V1 の下限を満たす。
  LEAK の負の対照と G3 で、今の歩の応えの混入はない。
- 言えないこと: 閉ループでの効果、TRM・正式な C0 の結果、生の世界への移行、比較機能や記憶一般の獲得、痕跡の維持費（この予備実験では払っていない）、
  `phenomenal_claim`。一つの世界の族・一つの法則・UNI の分布だけ。
